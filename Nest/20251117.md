- **NestJS 파일 컨벤션 (Naming Convention)**

	**NestJS의 파일 명명 규칙**
	- NestJS는 명확한 파일 구조와 명명 규칙을 권장
	- 파일명으로 역할을 쉽게 파악할 수 있도록 구조화
	- 각 파일은 하나의 책임만 가지도록 설계

	**기본 파일 구조**
	```
	src/
	├── users/
	│   ├── users.controller.ts      # HTTP 요청/응답 처리
	│   ├── users.service.ts         # 비즈니스 로직
	│   ├── users.module.ts          # 모듈 정의
	│   ├── users.entity.ts          # 데이터베이스 엔티티
	│   ├── dto/
	│   │   ├── create-user.dto.ts   # 생성 요청 DTO
	│   │   └── update-user.dto.ts   # 수정 요청 DTO
	│   └── users.controller.spec.ts # 테스트 파일
	├── app.module.ts
	└── main.ts
	```

	**파일 명명 규칙**
	- `*.controller.ts`: 컨트롤러 (HTTP 라우팅)
	- `*.service.ts`: 서비스 (비즈니스 로직)
	- `*.module.ts`: 모듈 (의존성 묶음)
	- `*.entity.ts`: 엔티티 (DB 스키마)
	- `*.dto.ts`: DTO (Data Transfer Object)
	- `*.guard.ts`: 가드 (인증/권한 체크)
	- `*.middleware.ts`: 미들웨어
	- `*.interceptor.ts`: 인터셉터
	- `*.pipe.ts`: 파이프 (데이터 변환/검증)
	- `*.filter.ts`: 예외 필터
	- `*.spec.ts`: 테스트 파일

	**폴더 구조 패턴**
	```typescript
	// 기능별 모듈 구조 (Feature Module Pattern)
	src/
	├── auth/           # 인증 모듈
	├── users/          # 사용자 모듈
	├── posts/          # 게시글 모듈
	├── common/         # 공통 기능
	│   ├── guards/
	│   ├── filters/
	│   └── decorators/
	└── config/         # 설정 파일
	```

- **NestJS CLI (Command Line Interface)**

	**NestJS CLI 설치**
	```bash
	npm install -g @nestjs/cli
	```

	**프로젝트 생성**
	```bash
	nest new project-name
	# 또는
	nest n project-name
	```

	**주요 CLI 명령어**

	**1. Generate (생성 명령어)**
	```bash
	# 모듈 생성
	nest generate module users
	nest g mo users  # 축약형

	# 컨트롤러 생성
	nest generate controller users
	nest g co users

	# 서비스 생성
	nest generate service users
	nest g s users

	# 리소스 생성 (CRUD 보일러플레이트 자동 생성)
	nest generate resource users
	nest g res users
	```

	**2. Resource 생성 시 옵션**
	```bash
	nest g resource users

	# 질문에 따라 선택:
	? What transport layer do you use? (Use arrow keys)
	❯ REST API
	  GraphQL (code first)
	  GraphQL (schema first)
	  Microservice (non-HTTP)
	  WebSockets

	? Would you like to generate CRUD entry points? (Y/n)
	```

	**Resource 명령어가 자동 생성하는 파일**
	```
	src/users/
	├── dto/
	│   ├── create-user.dto.ts
	│   └── update-user.dto.ts
	├── entities/
	│   └── user.entity.ts
	├── users.controller.ts      # GET, POST, PATCH, DELETE 엔드포인트
	├── users.service.ts         # CRUD 메서드 스켈레톤
	├── users.module.ts
	└── users.controller.spec.ts
	```

	**3. 기타 생성 명령어**
	```bash
	# 가드 생성
	nest g guard auth

	# 미들웨어 생성
	nest g middleware logger

	# 파이프 생성
	nest g pipe validation

	# 인터셉터 생성
	nest g interceptor logging

	# 필터 생성
	nest g filter http-exception

	# 데코레이터 생성
	nest g decorator user
	```

	**4. CLI 옵션**
	```bash
	# 특정 경로에 생성
	nest g s users/services/user

	# 테스트 파일 생성 안 함
	nest g s users --no-spec

	# Dry run (실제 생성 안 하고 미리보기)
	nest g res users --dry-run
	```

	**5. 프로젝트 관리 명령어**
	```bash
	# 개발 서버 시작
	nest start

	# Watch 모드로 시작 (코드 변경 감지)
	nest start --watch
	nest start -w

	# 디버그 모드
	nest start --debug
	nest start -d

	# 빌드
	nest build

	# 정보 확인
	nest info
	```

- **Swagger (API 문서화)**

	**Swagger란?**
	- RESTful API를 자동으로 문서화하는 도구
	- API 명세를 시각적으로 보여주고 테스트도 가능
	- OpenAPI 스펙을 기반으로 작동

	**설치**
	```bash
	npm install @nestjs/swagger swagger-ui-express
	```

	**기본 설정**
	```typescript
	// main.ts
	import { NestFactory } from '@nestjs/core';
	import { SwaggerModule, DocumentBuilder } from '@nestjs/swagger';
	import { AppModule } from './app.module';

	async function bootstrap() {
	  const app = await NestFactory.create(AppModule);

	  // Swagger 설정
	  const config = new DocumentBuilder()
	    .setTitle('Users API')
	    .setDescription('사용자 관리 API 문서')
	    .setVersion('1.0')
	    .addTag('users')
	    .addBearerAuth()  // JWT 인증 추가
	    .build();

	  const document = SwaggerModule.createDocument(app, config);
	  SwaggerModule.setup('api', app, document);  // /api 경로에서 접근

	  await app.listen(3000);
	}
	bootstrap();
	```

	**Swagger UI 접속**
	```
	http://localhost:3000/api
	```

	**Swagger 데코레이터 사용**

	**1. API 그룹화 (Tag)**
	```typescript
	import { ApiTags } from '@nestjs/swagger';

	@ApiTags('users')  // Swagger에서 그룹으로 묶임
	@Controller('users')
	export class UsersController {}
	```

	**2. API 엔드포인트 문서화**
	```typescript
	import { ApiOperation, ApiResponse } from '@nestjs/swagger';

	@Get(':id')
	@ApiOperation({ summary: '사용자 조회', description: 'ID로 특정 사용자를 조회합니다.' })
	@ApiResponse({ status: 200, description: '성공' })
	@ApiResponse({ status: 404, description: '사용자를 찾을 수 없음' })
	findOne(@Param('id') id: string) {
	  return this.usersService.findOne(+id);
	}
	```

	**3. DTO 문서화**
	```typescript
	import { ApiProperty } from '@nestjs/swagger';

	export class CreateUserDto {
	  @ApiProperty({
	    example: 'john@example.com',
	    description: '사용자 이메일',
	  })
	  email: string;

	  @ApiProperty({
	    example: 'password123',
	    description: '비밀번호',
	    minLength: 6,
	  })
	  password: string;

	  @ApiProperty({
	    example: 'John Doe',
	    description: '사용자 이름',
	    required: false,  // 선택적 필드
	  })
	  name?: string;
	}
	```

	**4. 인증 토큰 추가**
	```typescript
	import { ApiBearerAuth } from '@nestjs/swagger';

	@ApiBearerAuth()  // JWT 토큰 필요
	@Get('profile')
	getProfile() {
	  return this.usersService.getProfile();
	}
	```

	**5. 응답 스키마 정의**
	```typescript
	import { ApiProperty } from '@nestjs/swagger';

	export class UserEntity {
	  @ApiProperty()
	  id: number;

	  @ApiProperty()
	  email: string;

	  @ApiProperty()
	  name: string;
	}

	@Get()
	@ApiResponse({
	  status: 200,
	  description: '사용자 목록 조회 성공',
	  type: [UserEntity],  // 배열 응답
	})
	findAll(): UserEntity[] {
	  return this.usersService.findAll();
	}
	```

	**주요 Swagger 데코레이터**
	- `@ApiTags()`: API 그룹 태그
	- `@ApiOperation()`: 엔드포인트 설명
	- `@ApiResponse()`: 응답 상태 코드 문서화
	- `@ApiProperty()`: DTO 속성 문서화
	- `@ApiBearerAuth()`: JWT 인증 필요
	- `@ApiParam()`: URL 파라미터 문서화
	- `@ApiQuery()`: 쿼리 파라미터 문서화
	- `@ApiBody()`: 요청 본문 문서화

	**CLI로 DTO 자동 생성**
	```typescript
	// PartialType: 모든 필드를 optional로 변경
	import { PartialType } from '@nestjs/swagger';

	export class UpdateUserDto extends PartialType(CreateUserDto) {}
	```

**핵심 개념**:

**파일 컨벤션의 중요성**
- 일관된 명명 규칙으로 팀 협업 효율 증가
- 파일명만으로 역할을 즉시 파악 가능
- NestJS CLI와 호환되어 자동화 가능

**NestJS CLI의 장점**
- 보일러플레이트 코드 자동 생성으로 개발 속도 향상
- 일관된 코드 구조 유지
- Resource 명령어로 CRUD API를 몇 초 만에 생성

**Swagger의 핵심 가치**
- API 문서 자동 생성으로 문서 관리 부담 감소
- 프론트엔드 개발자와 협업 시 명확한 API 명세 공유
- Swagger UI에서 직접 API 테스트 가능

**예제 코드**:
```typescript
// 완전한 Swagger 적용 예제
import { Controller, Get, Post, Body, Param } from '@nestjs/common';
import { ApiTags, ApiOperation, ApiResponse, ApiProperty } from '@nestjs/swagger';

// DTO 정의
class CreateUserDto {
  @ApiProperty({ example: 'john@example.com' })
  email: string;

  @ApiProperty({ example: 'John Doe' })
  name: string;
}

// 컨트롤러
@ApiTags('users')
@Controller('users')
export class UsersController {
  @Post()
  @ApiOperation({ summary: '사용자 생성' })
  @ApiResponse({ status: 201, description: '생성 성공' })
  create(@Body() createUserDto: CreateUserDto) {
    return { id: 1, ...createUserDto };
  }

  @Get(':id')
  @ApiOperation({ summary: '사용자 조회' })
  @ApiResponse({ status: 200, description: '조회 성공' })
  @ApiResponse({ status: 404, description: '없음' })
  findOne(@Param('id') id: string) {
    return { id, email: 'john@example.com', name: 'John' };
  }
}
```

**결과**:
- `nest g resource` 명령어로 CRUD API 구조를 자동 생성할 수 있음
- Swagger UI에서 모든 API를 시각적으로 확인하고 테스트 가능
- 파일 컨벤션을 따르면 프로젝트 구조가 명확해져 유지보수가 용이함

## 💡 인사이트 & 깨달음

- NestJS CLI의 Resource 명령어는 단순히 파일만 생성하는 것이 아니라, REST API의 모범 사례를 코드로 제공한다는 점에서 매우 강력함
- Swagger 데코레이터를 코드에 추가하는 것이 처음엔 번거로워 보이지만, API 문서가 자동으로 동기화되므로 장기적으로는 엄청난 시간 절약
- 파일 명명 규칙을 지키는 것은 단순한 컨벤션이 아니라, CLI 자동화와 팀 협업의 기반이 됨
- Swagger는 백엔드 개발자가 프론트엔드 개발자에게 제공할 수 있는 최고의 선물 중 하나
