- **TypeORM 데이터베이스 커넥션 (Database Connection)**

	**TypeORM 커넥션이란?**
	- 애플리케이션과 데이터베이스를 연결하는 설정
	- 데이터베이스 타입, 호스트, 포트, 인증 정보 등을 포함
	- NestJS에서는 `TypeOrmModule.forRoot()`로 설정

	**기본 커넥션 설정**
	```typescript
	// app.module.ts
	import { TypeOrmModule } from '@nestjs/typeorm';

	@Module({
	  imports: [
	    TypeOrmModule.forRoot({
	      type: 'mysql',
	      host: 'localhost',
	      port: 3306,
	      username: 'root',
	      password: 'password',
	      database: 'test_db',
	      entities: [User, Post],
	      synchronize: false, // 운영 환경에서는 반드시 false
	      logging: true, // SQL 쿼리 로그 출력
	    }),
	  ],
	})
	export class AppModule {}
	```

	**환경변수를 활용한 커넥션 설정**
	```typescript
	// .env 파일
	DB_TYPE=mysql
	DB_HOST=localhost
	DB_PORT=3306
	DB_USERNAME=root
	DB_PASSWORD=password
	DB_DATABASE=test_db

	// app.module.ts
	import { ConfigModule, ConfigService } from '@nestjs/config';

	@Module({
	  imports: [
	    ConfigModule.forRoot({
	      isGlobal: true,
	    }),
	    TypeOrmModule.forRootAsync({
	      inject: [ConfigService],
	      useFactory: (configService: ConfigService) => ({
	        type: configService.get('DB_TYPE') as 'mysql',
	        host: configService.get('DB_HOST'),
	        port: configService.get<number>('DB_PORT'),
	        username: configService.get('DB_USERNAME'),
	        password: configService.get('DB_PASSWORD'),
	        database: configService.get('DB_DATABASE'),
	        entities: [__dirname + '/**/*.entity{.ts,.js}'],
	        synchronize: false,
	        logging: true,
	      }),
	    }),
	  ],
	})
	export class AppModule {}
	```

	**커넥션 주요 옵션**
	- `type`: 데이터베이스 종류 (mysql, postgres, sqlite 등)
	- `host`: 데이터베이스 호스트
	- `port`: 포트 번호
	- `username`: 사용자명
	- `password`: 비밀번호
	- `database`: 데이터베이스명
	- `entities`: Entity 클래스 배열
	- `synchronize`: Entity 기반으로 자동 테이블 생성/수정 (개발 환경에서만!)
	- `logging`: SQL 쿼리 로깅 여부
	- `migrations`: 마이그레이션 파일 경로
	- `migrationsRun`: 자동으로 마이그레이션 실행 여부
	- `ssl`: SSL 연결 설정
	- `poolSize`: 커넥션 풀 크기 (기본값: 10)

	**커넥션 풀 (Connection Pool)**
	```typescript
	TypeOrmModule.forRoot({

	  database: 'test_db',
	  poolSize: 20, // 동시 연결 수

	    connectionLimit: 20,
	    waitForConnections: true,
	    queueLimit: 0,
	```

- **Seeding (데이터 시딩)**

	**Seeding이란?**
	- 개발/테스트 환경에서 초기 데이터를 데이터베이스에 자동으로 삽입하는 작업
	- 테스트 데이터 생성, 샘플 데이터 제공 등의 목적
	- 매번 수동으로 데이터를 입력하지 않고 자동화

	**Seeding의 필요성**
	- 로컬 개발 환경 초기 설정 간소화
	- 테스트 환경에서 일관된 데이터 제공
	- 새로운 팀원의 온보딩 시간 단축
	- 데모/프레젠테이션용 샘플 데이터 생성

	**기본 Seeding 구현**
	```typescript
	// src/database/seeds/user.seeder.ts
	import { Injectable } from '@nestjs/common';
	import { InjectRepository } from '@nestjs/typeorm';
	import { Repository } from 'typeorm';
	import { User } from '../../entities/user.entity';

	@Injectable()
	export class UserSeeder {
	  constructor(
	    @InjectRepository(User)
	    private readonly userRepository: Repository<User>,
	  ) {}

	  async seed() {
	    const users = [
	      {
	        email: 'admin@example.com',
	        name: 'Admin User',
	        age: 30,
	      },
	      {
	        email: 'john@example.com',
	        name: 'John Doe',
	        age: 25,
	      },
	      {
	        email: 'jane@example.com',
	        name: 'Jane Smith',
	        age: 28,
	      },
	    ];

	    for (const userData of users) {
	      const existingUser = await this.userRepository.findOne({
	        where: { email: userData.email },
	      });

	      if (!existingUser) {
	        const user = this.userRepository.create(userData);
	        await this.userRepository.save(user);
	        console.log(`User ${userData.email} created`);
	      } else {
	        console.log(`User ${userData.email} already exists`);
	      }
	    }
	  }
	}
	```

	**Seeding 명령어 스크립트 생성**
	```typescript
	// src/database/seeds/seed.ts
	import { NestFactory } from '@nestjs/core';
	import { AppModule } from '../../app.module';
	import { UserSeeder } from './user.seeder';
	import { PostSeeder } from './post.seeder';

	async function bootstrap() {
	  const app = await NestFactory.createApplicationContext(AppModule);

	  const userSeeder = app.get(UserSeeder);
	  const postSeeder = app.get(PostSeeder);

	  console.log('Starting seeding...');

	  await userSeeder.seed();
	  await postSeeder.seed();

	  console.log('Seeding completed!');

	  await app.close();
	}

	bootstrap();
	```


	**관계가 있는 데이터 Seeding**
	```typescript
	@Injectable()
	export class PostSeeder {
	  constructor(
	    @InjectRepository(Post)
	    private readonly postRepository: Repository<Post>,
	    @InjectRepository(User)
	    private readonly userRepository: Repository<User>,
	  ) {}

	  async seed() {
	    const users = await this.userRepository.find();

	    if (users.length === 0) {
	      console.log('No users found. Please run user seeder first.');
	      return;
	    }

	    for (const user of users) {
	      // 각 사용자에게 3~5개의 게시글 생성
	      const postCount = faker.number.int({ min: 3, max: 5 });

	      for (let i = 0; i < postCount; i++) {
	        const post = this.postRepository.create({
	          title: faker.lorem.sentence(),
	          content: faker.lorem.paragraphs(3),
	          user: user,
	        });

	        await this.postRepository.save(post);
	      }
	    }

	    console.log('Posts seeded successfully');
	  }
	}
	```

- **Migration (마이그레이션)**

	**Migration이란?**
	- 데이터베이스 스키마의 변경 이력을 버전 관리하는 시스템
	- 테이블 생성, 수정, 삭제를 코드로 관리
	- `synchronize: true` 대신 운영 환경에서 사용하는 안전한 방법
	- 팀원 간 데이터베이스 스키마 동기화

	**Migration이 필요한 이유**
	- **안전성**: `synchronize: true`는 운영 환경에서 데이터 손실 위험
	- **버전 관리**: 스키마 변경 이력 추적 가능
	- **롤백**: 문제 발생 시 이전 상태로 되돌리기 가능
	- **협업**: 팀원 간 동일한 데이터베이스 구조 유지
	- **배포**: 자동화된 배포 파이프라인에 통합 가능

	**TypeORM CLI 설정**

	**외래 키 추가 마이그레이션**
	```typescript
	import { MigrationInterface, QueryRunner, TableForeignKey } from 'typeorm';

	export class AddUserForeignKeyToPosts1700000000002 implements MigrationInterface {
	  public async up(queryRunner: QueryRunner): Promise<void> {
	    await queryRunner.createForeignKey(
	      'posts',
	      new TableForeignKey({
	        columnNames: ['user_id'],
	        referencedTableName: 'users',
	        referencedColumnNames: ['id'],
	        onDelete: 'CASCADE',
	        onUpdate: 'CASCADE',
	      }),
	    );
	  }

	  public async down(queryRunner: QueryRunner): Promise<void> {
	    const table = await queryRunner.getTable('posts');
	    const foreignKey = table.foreignKeys.find(
	      (fk) => fk.columnNames.indexOf('user_id') !== -1,
	    );
	    await queryRunner.dropForeignKey('posts', foreignKey);
	  }
	}
	```

	**데이터 마이그레이션 (Data Migration)**
	```typescript
	import { MigrationInterface, QueryRunner } from 'typeorm';

	export class UpdateUserRoles1700000000004 implements MigrationInterface {
	  public async up(queryRunner: QueryRunner): Promise<void> {
	    // 컬럼 추가
	    await queryRunner.query(`
	      ALTER TABLE users ADD COLUMN role VARCHAR(20) DEFAULT 'user'
	    `);

	    // 기존 데이터 업데이트
	    await queryRunner.query(`
	      UPDATE users SET role = 'admin' WHERE email = 'admin@example.com'
	    `);
	  }

	  public async down(queryRunner: QueryRunner): Promise<void> {
	    await queryRunner.query(`
	      ALTER TABLE users DROP COLUMN role
	    `);
	  }
	}
	```

	**마이그레이션 베스트 프랙티스**
	1. **항상 `up`과 `down` 메서드 작성**: 롤백 가능하도록
	2. **작은 단위로 분리**: 한 마이그레이션에 하나의 목적만
	3. **운영 환경 적용 전 테스트**: 로컬/스테이징에서 충분히 검증
	4. **백업 필수**: 운영 DB 마이그레이션 전 반드시 백업
	5. **순차 실행**: 마이그레이션은 순서대로 실행됨을 유의

**핵심 개념**:

**TypeORM 커넥션의 3가지 설정 방법**
1. **직접 설정**: `TypeOrmModule.forRoot()`에 직접 객체 전달
2. **환경변수 활용**: `forRootAsync()`와 ConfigService 조합
3. **별도 파일 관리**: `ormconfig.ts` 또는 `data-source.ts`로 분리

**Seeding vs Migration**
- **Seeding**: 초기 데이터 삽입 (개발/테스트용 샘플 데이터)
- **Migration**: 스키마 변경 관리 (테이블 구조 변경)
- **함께 사용**: Migration으로 스키마 생성 → Seeding으로 데이터 삽입

**synchronize: true의 위험성**
- 개발 환경에서만 사용
- 운영 환경에서는 **절대 금지** (데이터 손실 위험)
- 대신 Migration을 사용하여 안전하게 스키마 관리

**마이그레이션 워크플로우**
```
Entity 수정
    ↓
migration:generate (자동 감지)
    ↓
마이그레이션 파일 생성
    ↓
코드 리뷰
    ↓
migration:run (실행)
    ↓
문제 발생 시 migration:revert (롤백)
```

**예제 코드**:
```typescript
// 완전한 예제 - 커넥션 → 마이그레이션 → Seeding

// 1. 데이터베이스 커넥션 설정 (ormconfig.ts)
import { DataSource } from 'typeorm';
import { User } from './src/entities/user.entity';
import { Post } from './src/entities/post.entity';

export const AppDataSource = new DataSource({
  type: 'mysql',
  host: process.env.DB_HOST || 'localhost',
  port: parseInt(process.env.DB_PORT) || 3306,
  username: process.env.DB_USERNAME || 'root',
  password: process.env.DB_PASSWORD || 'password',
  database: process.env.DB_DATABASE || 'test_db',
  entities: [User, Post],
  migrations: ['src/migrations/*.ts'],
  synchronize: false, // 운영 환경 필수!
  logging: true,
});

// 2. 마이그레이션 생성 및 실행
// bash: npm run migration:generate -- src/migrations/InitialSchema
// bash: npm run migration:run

// src/migrations/1700000000000-InitialSchema.ts
export class InitialSchema1700000000000 implements MigrationInterface {
  public async up(queryRunner: QueryRunner): Promise<void> {
    // users 테이블 생성
    await queryRunner.createTable(
      new Table({
        name: 'users',
        columns: [
          {
            name: 'id',
            type: 'int',
            isPrimary: true,
            isGenerated: true,
            generationStrategy: 'increment',
          },
          {
            name: 'email',
            type: 'varchar',
            isUnique: true,
          },
          {
            name: 'name',
            type: 'varchar',
          },
        ],
      }),
      true,
    );

@Injectable()
export class PostSeeder {
  constructor(
    @InjectRepository(Post)
    private readonly postRepository: Repository<Post>,
    @InjectRepository(User)
    private readonly userRepository: Repository<User>,
  ) {}

  async seed() {

    const users = await this.userRepository.find();

    for (const user of users) {
      const postCount = faker.number.int({ min: 2, max: 5 });

      for (let i = 0; i < postCount; i++) {
        const post = this.postRepository.create({
          title: faker.lorem.sentence(),
          content: faker.lorem.paragraphs(3),
          user: user,
        });
        await this.postRepository.save(post);
      }
    }

    console.log('Posts seeded successfully');
  }
}
```

## 💡 인사이트 & 깨달음

- **synchronize: true는 개발 편의성의 함정**: 처음엔 편하지만, 운영 환경에서 치명적인 데이터 손실 발생 가능. 처음부터 Migration 습관 들이기
- **Migration은 코드로 관리하는 DB 히스토리**: Git 커밋처럼 스키마 변경 이력을 코드로 관리하면 "누가, 언제, 왜" 변경했는지 추적 가능
- **Seeding과 Faker의 조합**: 실제와 유사한 랜덤 데이터를 대량으로 생성하여, 성능 테스트와 UI 테스트에 활용 가능
- **up과 down의 중요성**: 마이그레이션 작성 시 항상 롤백 시나리오를 고려. 운영 환경에서 문제 발생 시 빠른 복구가 생명
- **환경변수로 커넥션 분리**: 하드코딩된 DB 정보는 보안 위험. 환경변수와 .gitignore로 민감 정보 보호
- **마이그레이션은 순차적**: 팀원 A가 만든 마이그레이션과 팀원 B가 만든 마이그레이션의 실행 순서 충돌 주의. 머지 전 확인 필수
- **커넥션 풀 크기 최적화**: 너무 작으면 병목 발생, 너무 크면 DB 리소스 낭비. 트래픽 패턴에 맞게 조정
- **데이터 마이그레이션의 양면성**: 스키마뿐 아니라 기존 데이터 변환도 마이그레이션으로 관리 가능하지만, 대용량 데이터는 별도 전략 필요
