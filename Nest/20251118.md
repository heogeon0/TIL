#### 상세 내용

- **커스텀 데코레이터 (Custom Decorator)**

	**데코레이터란?**
	- `@` 기호로 시작하는 특별한 선언
	- 클래스, 메서드, 파라미터에 메타데이터를 추가하거나 기능을 확장
	- NestJS는 데코레이터를 통해 의존성 주입, 라우팅, 검증 등을 처리

	**커스텀 데코레이터가 필요한 이유**
	- 반복되는 코드를 데코레이터로 추상화
	- 코드 가독성과 재사용성 향상
	- 비즈니스 로직과 부가 기능 분리

	**파라미터 데코레이터 생성**
	```typescript
	import { createParamDecorator, ExecutionContext } from '@nestjs/common';

	// 현재 로그인한 사용자 정보를 추출하는 데코레이터
	export const CurrentUser = createParamDecorator(
	  (data: unknown, ctx: ExecutionContext) => {
	    const request = ctx.switchToHttp().getRequest();
	    return request.user; // req.user를 반환
	  },
	);
	```

	**사용 예제**
	```typescript
	@Controller('users')
	export class UsersController {
	  @Get('profile')
	  getProfile(@CurrentUser() user: User) {
	    // req.user 대신 @CurrentUser()로 간단하게 접근
	    return user;
	  }
	}
	```

	**특정 속성만 추출하는 데코레이터**
	```typescript
	export const UserId = createParamDecorator(
	  (data: unknown, ctx: ExecutionContext) => {
	    const request = ctx.switchToHttp().getRequest();
	    return request.user?.id; // user.id만 반환
	  },
	);

	// 사용
	@Get('my-posts')
	getMyPosts(@UserId() userId: number) {
	  return this.postsService.findByUser(userId);
	}
	```

	**데이터를 전달받는 데코레이터**
	```typescript
	export const User = createParamDecorator(
	  (data: string, ctx: ExecutionContext) => {
	    const request = ctx.switchToHttp().getRequest();
	    const user = request.user;

	    // data로 특정 필드만 반환 가능
	    return data ? user?.[data] : user;
	  },
	);

	// 사용
	@Get('profile')
	getProfile(@User('email') email: string) {
	  return { email };
	}
	```

	**메서드 데코레이터 (복합 데코레이터)**
	```typescript
	import { applyDecorators, UseGuards } from '@nestjs/common';
	import { ApiBearerAuth, ApiUnauthorizedResponse } from '@nestjs/swagger';

	// 여러 데코레이터를 하나로 묶음
	export function Auth(...roles: string[]) {
	  return applyDecorators(
	    UseGuards(AuthGuard, RolesGuard),
	    ApiBearerAuth(),
	    ApiUnauthorizedResponse({ description: '인증 실패' }),
	  );
	}

	// 사용 - 여러 줄의 데코레이터를 한 줄로 단순화
	@Auth('admin')
	@Get('admin')
	adminOnly() {
	  return '관리자 전용';
	}
	```

- **인터셉터 (Interceptor)**

	**인터셉터란?**
	- 요청/응답을 가로채서 추가 로직을 실행하는 미들웨어
	- 메서드 실행 전후에 동작 가능
	- RxJS Observable을 활용한 스트림 기반 처리

	**인터셉터의 주요 용도**
	- 응답 데이터 변환 (transform)
	- 로깅 및 성능 측정
	- 응답 포맷 통일
	- 캐싱
	- 에러 처리

	**기본 인터셉터 구조**
	```typescript
	import { Injectable, NestInterceptor, ExecutionContext, CallHandler } from '@nestjs/common';
	import { Observable } from 'rxjs';
	import { tap } from 'rxjs/operators';

	@Injectable()
	export class LoggingInterceptor implements NestInterceptor {
	  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
	    console.log('Before...');

	    const now = Date.now();
	    return next
	      .handle()
	      .pipe(
	        tap(() => console.log(`After... ${Date.now() - now}ms`)),
	      );
	  }
	}
	```

	**실행 흐름**
	```
	Request → 인터셉터 before → Controller → Service → 인터셉터 after → Response
	```

	**응답 데이터 변환 인터셉터**
	```typescript
	import { Injectable, NestInterceptor, ExecutionContext, CallHandler } from '@nestjs/common';
	import { Observable } from 'rxjs';
	import { map } from 'rxjs/operators';

	export interface Response<T> {
	  success: boolean;
	  data: T;
	  timestamp: string;
	}

	@Injectable()
	export class TransformInterceptor<T> implements NestInterceptor<T, Response<T>> {
	  intercept(context: ExecutionContext, next: CallHandler): Observable<Response<T>> {
	    return next.handle().pipe(
	      map(data => ({
	        success: true,
	        data,
	        timestamp: new Date().toISOString(),
	      })),
	    );
	  }
	}
	```

	**적용 전 응답**
	```json
	{
	  "id": 1,
	  "name": "John"
	}
	```

	**적용 후 응답**
	```json
	{
	  "success": true,
	  "data": {
	    "id": 1,
	    "name": "John"
	  },
	  "timestamp": "2025-11-18T12:00:00.000Z"
	}
	```

	**인터셉터 적용 방법**

	**1. 메서드 레벨**
	```typescript
	@UseInterceptors(LoggingInterceptor)
	@Get()
	findAll() {
	  return this.usersService.findAll();
	}
	```

	**2. 컨트롤러 레벨**
	```typescript
	@UseInterceptors(LoggingInterceptor)
	@Controller('users')
	export class UsersController {}
	```

	**3. 전역 레벨**
	```typescript
	// main.ts
	const app = await NestFactory.create(AppModule);
	app.useGlobalInterceptors(new LoggingInterceptor());
	```

	**성능 측정 인터셉터**
	```typescript
	@Injectable()
	export class PerformanceInterceptor implements NestInterceptor {
	  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
	    const request = context.switchToHttp().getRequest();
	    const { method, url } = request;
	    const start = Date.now();

	    return next.handle().pipe(
	      tap(() => {
	        const duration = Date.now() - start;
	        console.log(`${method} ${url} - ${duration}ms`);
	      }),
	    );
	  }
	}
	```

- **AOP (Aspect-Oriented Programming, 관점 지향 프로그래밍)**

	**AOP란?**
	- 비즈니스 로직과 부가 기능(횡단 관심사)을 분리하는 프로그래밍 패러다임
	- 로깅, 트랜잭션, 보안, 캐싱 등 여러 곳에서 반복되는 코드를 한곳에 모아 관리
	- NestJS는 데코레이터와 인터셉터를 통해 AOP를 구현

	**횡단 관심사 (Cross-Cutting Concerns)**
	- 여러 모듈/계층에 걸쳐 공통으로 필요한 기능
	- 예: 로깅, 인증, 트랜잭션, 예외 처리, 캐싱

	**AOP 없이 작성한 코드 (반복되는 로깅)**
	```typescript
	@Controller('users')
	export class UsersController {
	  @Get()
	  findAll() {
	    console.log('[UsersController] findAll 시작');
	    const result = this.usersService.findAll();
	    console.log('[UsersController] findAll 완료');
	    return result;
	  }

	  @Get(':id')
	  findOne(@Param('id') id: string) {
	    console.log('[UsersController] findOne 시작');
	    const result = this.usersService.findOne(id);
	    console.log('[UsersController] findOne 완료');
	    return result;
	  }
	}
	```

	**AOP 적용 (인터셉터로 로깅 분리)**
	```typescript
	@UseInterceptors(LoggingInterceptor) // 한 줄로 모든 메서드에 로깅 적용
	@Controller('users')
	export class UsersController {
	  @Get()
	  findAll() {
	    return this.usersService.findAll();
	  }

	  @Get(':id')
	  findOne(@Param('id') id: string) {
	    return this.usersService.findOne(id);
	  }
	}
	```

	**NestJS의 AOP 구현 요소**

	| 요소 | 역할 | 횡단 관심사 예시 |
	|------|------|------------------|
	| **Middleware** | 라우터 핸들러 전에 실행 | 요청 로깅, CORS |
	| **Guard** | 요청 허용 여부 결정 | 인증, 권한 체크 |
	| **Interceptor** | 요청/응답 변환, 확장 | 로깅, 캐싱, 응답 변환 |
	| **Pipe** | 데이터 검증, 변환 | 유효성 검증, 타입 변환 |
	| **Exception Filter** | 예외 처리 | 에러 응답 포맷 통일 |

	**실행 순서**
	```
	Request
	    ↓
	Middleware
	    ↓
	Guard
	    ↓
	Interceptor (before)
	    ↓
	Pipe
	    ↓
	Controller/Service
	    ↓
	Interceptor (after)
	    ↓
	Exception Filter (에러 발생 시)
	    ↓
	Response
	```

	**AOP의 장점**
	```typescript
	// ❌ AOP 없이 - 비즈니스 로직과 부가 기능이 섞임
	@Get()
	findAll() {
	  console.log('로깅');
	  if (!user) throw new Error(); // 인증
	  const start = Date.now(); // 성능 측정
	  const result = this.service.findAll(); // 핵심 로직
	  console.log(Date.now() - start);
	  return result;
	}

	// ✅ AOP 적용 - 핵심 로직만 남음
	@UseGuards(AuthGuard)
	@UseInterceptors(LoggingInterceptor, PerformanceInterceptor)
	@Get()
	findAll() {
	  return this.service.findAll(); // 핵심 비즈니스 로직만
	}
	```

**핵심 개념**:

**커스텀 데코레이터**
- 반복되는 코드 패턴을 데코레이터로 추상화
- `createParamDecorator`로 파라미터 데코레이터 생성
- `applyDecorators`로 여러 데코레이터를 하나로 묶기 가능
- 코드 재사용성과 가독성 향상

**인터셉터의 핵심 역할**
- 요청/응답 흐름을 가로채서 추가 로직 실행
- RxJS의 `pipe`와 `tap`, `map` 등으로 데이터 스트림 조작
- 로깅, 변환, 캐싱, 성능 측정 등에 활용
- 전역, 컨트롤러, 메서드 레벨에서 유연하게 적용 가능

**AOP의 핵심 가치**
- 비즈니스 로직과 부가 기능(횡단 관심사)의 분리
- 코드 중복 제거와 유지보수성 향상
- NestJS는 Middleware, Guard, Interceptor, Pipe, Filter로 AOP 구현
- 데코레이터 기반으로 선언적이고 직관적인 코드 작성 가능

**예제 코드**:
```typescript
// 커스텀 데코레이터 + 인터셉터 + AOP 종합 예제

// 1. 커스텀 데코레이터
import { createParamDecorator, ExecutionContext } from '@nestjs/common';

export const CurrentUser = createParamDecorator(
  (data: unknown, ctx: ExecutionContext) => {
    const request = ctx.switchToHttp().getRequest();
    return request.user;
  },
);

// 2. 인터셉터 (응답 변환)
import { Injectable, NestInterceptor, CallHandler } from '@nestjs/common';
import { map } from 'rxjs/operators';

@Injectable()
export class ResponseInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler) {
    return next.handle().pipe(
      map(data => ({
        success: true,
        data,
        timestamp: new Date().toISOString(),
      })),
    );
  }
}

// 3. AOP 적용 - 컨트롤러
import { Controller, Get, UseInterceptors, UseGuards } from '@nestjs/common';

@UseGuards(AuthGuard) // 인증 체크 (횡단 관심사)
@UseInterceptors(ResponseInterceptor) // 응답 변환 (횡단 관심사)
@Controller('posts')
export class PostsController {
  @Get()
  findAll(@CurrentUser() user: User) {
    // 핵심 비즈니스 로직만 남음
    return this.postsService.findByUser(user.id);
  }
}
```

**결과**:
- 커스텀 데코레이터로 반복 코드를 줄이고 가독성 향상
- 인터셉터로 응답 포맷을 자동으로 통일하여 일관성 확보
- AOP 패턴으로 비즈니스 로직과 부가 기능을 명확히 분리
- 코드의 재사용성과 유지보수성이 크게 향상됨

## 💡 인사이트 & 깨달음

- 커스텀 데코레이터는 단순히 편의 기능이 아니라, 코드의 의도를 명확히 드러내는 강력한 도구임
- 인터셉터의 RxJS 기반 스트림 처리는 처음엔 생소하지만, 함수형 프로그래밍의 강력함을 보여줌
- AOP는 "무엇을 할 것인가(비즈니스 로직)"와 "어떻게 할 것인가(부가 기능)"를 분리하는 핵심 원칙
- NestJS의 데코레이터 패턴은 Spring의 AOP와 유사하지만, TypeScript의 데코레이터 문법으로 더 직관적으로 표현됨
- 횡단 관심사를 잘 분리하면, 새로운 기능 추가 시 기존 코드를 거의 수정하지 않아도 됨 (OCP 원칙)
