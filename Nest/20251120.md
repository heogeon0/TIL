#### 상세 내용

- **TypeORM 기초**

	**TypeORM이란?**
	- TypeScript와 JavaScript를 위한 ORM (Object-Relational Mapping) 라이브러리
	- 데이터베이스 테이블을 TypeScript 클래스로 매핑하여 객체 지향적으로 데이터 관리
	- MySQL, PostgreSQL, SQLite, MSSQL 등 다양한 데이터베이스 지원
	- NestJS와 완벽하게 통합되어 사용 가능

	**ORM의 장점**
	- SQL을 직접 작성하지 않고 TypeScript 코드로 데이터베이스 조작
	- 타입 안정성으로 컴파일 타임에 에러 검출
	- 데이터베이스 변경 시 코드 수정 최소화
	- 자동 마이그레이션 지원

	**설치**
	```bash
	npm install @nestjs/typeorm typeorm mysql2
	# 또는 PostgreSQL 사용 시
	npm install @nestjs/typeorm typeorm pg
	```

	**기본 설정**
	```typescript
	// app.module.ts
	import { TypeOrmModule } from '@nestjs/typeorm';

	@Module({
	  imports: [
	    TypeOrmModule.forRoot({
	      type: 'mysql',
	      host: 'localhost',
	      port: 3306,
	      username: 'root',
	      password: 'password',
	      database: 'test',
	      entities: [User, Post], // 엔티티 등록
	      synchronize: true, // 개발 환경에서만 true (운영에서는 false)
	    }),
	  ],
	})
	export class AppModule {}
	```

	**Entity 정의**
	```typescript
	import { Entity, PrimaryGeneratedColumn, Column } from 'typeorm';

	@Entity('users') // 테이블 이름
	export class User {
	  @PrimaryGeneratedColumn()
	  id: number;

	  @Column({ type: 'varchar', length: 100, unique: true })
	  email: string;

	  @Column({ type: 'varchar', length: 50 })
	  name: string;

	  @Column({ type: 'int', default: 0 })
	  age: number;

	  @Column({ type: 'timestamp', default: () => 'CURRENT_TIMESTAMP' })
	  createdAt: Date;
	}
	```

	**주요 데코레이터**
	- `@Entity()`: 클래스를 데이터베이스 테이블로 매핑
	- `@PrimaryGeneratedColumn()`: 자동 증가 Primary Key
	- `@PrimaryColumn()`: 수동으로 지정하는 Primary Key
	- `@Column()`: 테이블 컬럼 정의
	- `@CreateDateColumn()`: 생성 시간 자동 기록
	- `@UpdateDateColumn()`: 수정 시간 자동 기록
	- `@DeleteDateColumn()`: Soft Delete 시간 기록

	**Repository 사용하기**
	```typescript
	// user.module.ts
	import { TypeOrmModule } from '@nestjs/typeorm';

	@Module({
	  imports: [TypeOrmModule.forFeature([User])],
	  controllers: [UserController],
	  providers: [UserService],
	})
	export class UserModule {}

	// user.service.ts
	import { InjectRepository } from '@nestjs/typeorm';
	import { Repository } from 'typeorm';

	@Injectable()
	export class UserService {
	  constructor(
	    @InjectRepository(User)
	    private userRepository: Repository<User>,
	  ) {}

	  // 전체 조회
	  async findAll(): Promise<User[]> {
	    return this.userRepository.find();
	  }

	  // ID로 조회
	  async findOne(id: number): Promise<User> {
	    return this.userRepository.findOne({ where: { id } });
	  }

	  // 생성
	  async create(userData: CreateUserDto): Promise<User> {
	    const user = this.userRepository.create(userData);
	    return this.userRepository.save(user);
	  }

	  // 수정
	  async update(id: number, userData: UpdateUserDto): Promise<User> {
	    await this.userRepository.update(id, userData);
	    return this.findOne(id);
	  }

	  // 삭제
	  async remove(id: number): Promise<void> {
	    await this.userRepository.delete(id);
	  }
	}
	```

- **TypeORM 관계 설정 (Relations)**

	**관계의 종류**
	- **One-to-One (1:1)**: 한 엔티티가 다른 엔티티와 1:1 관계
	- **One-to-Many (1:N)**: 한 엔티티가 여러 엔티티와 관계
	- **Many-to-One (N:1)**: 여러 엔티티가 한 엔티티와 관계
	- **Many-to-Many (N:M)**: 여러 엔티티가 서로 여러 엔티티와 관계

	**One-to-One 관계**
	```typescript
	// User 엔티티
	@Entity()
	export class User {
	  @PrimaryGeneratedColumn()
	  id: number;

	  @Column()
	  name: string;

	  // User는 하나의 Profile을 가짐
	  @OneToOne(() => Profile, profile => profile.user, { cascade: true })
	  @JoinColumn() // 외래 키를 가지는 쪽에 설정
	  profile: Profile;
	}

	// Profile 엔티티
	@Entity()
	export class Profile {
	  @PrimaryGeneratedColumn()
	  id: number;

	  @Column()
	  bio: string;

	  @Column()
	  avatar: string;

	  @OneToOne(() => User, user => user.profile)
	  user: User;
	}
	```

	**One-to-Many / Many-to-One 관계 (가장 일반적)**
	```typescript
	// User 엔티티 (One)
	@Entity()
	export class User {
	  @PrimaryGeneratedColumn()
	  id: number;

	  @Column()
	  name: string;

	  // 한 명의 User는 여러 개의 Post를 작성할 수 있음
	  @OneToMany(() => Post, post => post.user)
	  posts: Post[];
	}

	// Post 엔티티 (Many)
	@Entity()
	export class Post {
	  @PrimaryGeneratedColumn()
	  id: number;

	  @Column()
	  title: string;

	  @Column()
	  content: string;

	  // 여러 개의 Post는 한 명의 User에 속함
	  @ManyToOne(() => User, user => user.posts, { onDelete: 'CASCADE' })
	  @JoinColumn({ name: 'user_id' }) // 외래 키 컬럼명 지정
	  user: User;

	  @Column({ name: 'user_id' })
	  userId: number; // 외래 키 값 직접 접근용
	}
	```

	**Many-to-Many 관계**
	```typescript
	// Student 엔티티
	@Entity()
	export class Student {
	  @PrimaryGeneratedColumn()
	  id: number;

	  @Column()
	  name: string;

	  // 한 학생은 여러 과목을 수강
	  @ManyToMany(() => Course, course => course.students)
	  @JoinTable({ // 중간 테이블 생성 (한쪽에만 설정)
	    name: 'student_courses',
	    joinColumn: { name: 'student_id', referencedColumnName: 'id' },
	    inverseJoinColumn: { name: 'course_id', referencedColumnName: 'id' },
	  })
	  courses: Course[];
	}

	// Course 엔티티
	@Entity()
	export class Course {
	  @PrimaryGeneratedColumn()
	  id: number;

	  @Column()
	  title: string;

	  // 한 과목은 여러 학생이 수강
	  @ManyToMany(() => Student, student => student.courses)
	  students: Student[];
	}
	```

	**관계 옵션**
	- `cascade`: 연관 엔티티 자동 저장/삭제
		- `cascade: true` 또는 `cascade: ['insert', 'update']`
	- `eager`: 자동으로 관계 로드 (find 시 자동 JOIN)
		- `eager: true`
	- `lazy`: 지연 로딩 (필요할 때만 로드)
	- `onDelete`: 부모 삭제 시 동작 설정
		- `CASCADE`: 부모 삭제 시 자식도 삭제
		- `SET NULL`: 부모 삭제 시 외래 키를 NULL로
		- `RESTRICT`: 자식이 있으면 부모 삭제 불가

	**관계 데이터 조회**
	```typescript
	// 관계 데이터 포함해서 조회
	const users = await this.userRepository.find({
	  relations: ['posts', 'profile'],
	});

	// 특정 조건으로 관계 데이터 조회
	const user = await this.userRepository.findOne({
	  where: { id: 1 },
	  relations: ['posts'],
	});

	// QueryBuilder 사용
	const users = await this.userRepository
	  .createQueryBuilder('user')
	  .leftJoinAndSelect('user.posts', 'post')
	  .where('user.id = :id', { id: 1 })
	  .getMany();
	```

- **TypeORM Model Generator**

	**typeorm-model-generator란?**
	- 기존 데이터베이스로부터 자동으로 TypeORM Entity를 생성하는 도구
	- 레거시 데이터베이스를 TypeORM으로 마이그레이션할 때 유용
	- 수동으로 엔티티를 작성하는 시간을 크게 절약

	**설치**
	```bash
	npm install -g typeorm-model-generator
	```

	**사용법**
	```bash
	# MySQL
	typeorm-model-generator -h localhost -d database_name -u root -x password -e mysql -o ./src/entities

	# PostgreSQL
	typeorm-model-generator -h localhost -d database_name -u postgres -x password -e postgres -o ./src/entities

	# 옵션 설명
	# -h: 호스트
	# -d: 데이터베이스명
	# -u: 사용자명
	# -x: 비밀번호
	# -e: 데이터베이스 엔진 (mysql, postgres, mssql 등)
	# -o: 출력 경로
	```

	**생성된 Entity 예시**
	```typescript
	// 자동 생성된 파일
	import { Column, Entity, PrimaryGeneratedColumn } from 'typeorm';

	@Entity('users', { schema: 'public' })
	export class Users {
	  @PrimaryGeneratedColumn({ type: 'int', name: 'id' })
	  id: number;

	  @Column('varchar', { name: 'email', unique: true, length: 100 })
	  email: string;

	  @Column('varchar', { name: 'name', length: 50 })
	  name: string;

	  @Column('timestamp', {
	    name: 'created_at',
	    default: () => 'CURRENT_TIMESTAMP',
	  })
	  createdAt: Date;
	}
	```

	**장점**
	- 기존 데이터베이스 스키마를 빠르게 TypeORM으로 변환
	- 관계 설정까지 자동 생성
	- 대규모 데이터베이스 마이그레이션 시 시간 절약

	**단점**
	- 생성된 코드를 프로젝트 스타일에 맞게 수정 필요
	- 엔티티명이 테이블명 그대로 생성되어 리팩토링 필요할 수 있음

- **SQL 기초**

	**SQL이란?**
	- Structured Query Language (구조화 질의 언어)
	- 데이터베이스에서 데이터를 관리하기 위한 표준 언어
	- DDL, DML, DCL, TCL로 구분

	**SQL 명령어 분류**

	**1. DDL (Data Definition Language) - 데이터 정의어**
	```sql
	-- 테이블 생성
	CREATE TABLE users (
	  id INT PRIMARY KEY AUTO_INCREMENT,
	  email VARCHAR(100) UNIQUE NOT NULL,
	  name VARCHAR(50) NOT NULL,
	  age INT DEFAULT 0,
	  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
	);

	-- 테이블 수정
	ALTER TABLE users ADD COLUMN phone VARCHAR(20);
	ALTER TABLE users MODIFY COLUMN name VARCHAR(100);
	ALTER TABLE users DROP COLUMN age;

	-- 테이블 삭제
	DROP TABLE users;

	-- 테이블 초기화 (데이터만 삭제)
	TRUNCATE TABLE users;
	```

	**2. DML (Data Manipulation Language) - 데이터 조작어**
	```sql
	-- 데이터 삽입 (INSERT)
	INSERT INTO users (email, name, age)
	VALUES ('john@example.com', 'John Doe', 25);

	-- 여러 행 삽입
	INSERT INTO users (email, name, age) VALUES
	  ('alice@example.com', 'Alice', 30),
	  ('bob@example.com', 'Bob', 28);

	-- 데이터 조회 (SELECT)
	SELECT * FROM users;
	SELECT email, name FROM users;
	SELECT * FROM users WHERE age > 25;
	SELECT * FROM users WHERE name LIKE 'John%';
	SELECT * FROM users ORDER BY created_at DESC;
	SELECT * FROM users LIMIT 10 OFFSET 20; -- 페이징

	-- 데이터 수정 (UPDATE)
	UPDATE users SET age = 26 WHERE email = 'john@example.com';
	UPDATE users SET name = 'John Smith', age = 27 WHERE id = 1;

	-- 데이터 삭제 (DELETE)
	DELETE FROM users WHERE id = 1;
	DELETE FROM users WHERE age < 18;
	```

	**3. 조인 (JOIN) - 테이블 결합**
	```sql
	-- INNER JOIN: 양쪽 테이블에 모두 존재하는 데이터만
	SELECT users.name, posts.title
	FROM users
	INNER JOIN posts ON users.id = posts.user_id;

	-- LEFT JOIN: 왼쪽 테이블의 모든 데이터 + 오른쪽 매칭 데이터
	SELECT users.name, posts.title
	FROM users
	LEFT JOIN posts ON users.id = posts.user_id;

	-- RIGHT JOIN: 오른쪽 테이블의 모든 데이터 + 왼쪽 매칭 데이터
	SELECT users.name, posts.title
	FROM users
	RIGHT JOIN posts ON users.id = posts.user_id;
	```

	**4. 집계 함수 (Aggregate Functions)**
	```sql
	-- COUNT: 행 개수
	SELECT COUNT(*) FROM users;
	SELECT COUNT(DISTINCT email) FROM users;

	-- SUM: 합계
	SELECT SUM(age) FROM users;

	-- AVG: 평균
	SELECT AVG(age) FROM users;

	-- MAX, MIN: 최대값, 최소값
	SELECT MAX(age), MIN(age) FROM users;

	-- GROUP BY: 그룹화
	SELECT age, COUNT(*) as count
	FROM users
	GROUP BY age;

	-- HAVING: 그룹 조건
	SELECT age, COUNT(*) as count
	FROM users
	GROUP BY age
	HAVING count > 5;
	```

	**5. 서브쿼리 (Subquery)**
	```sql
	-- WHERE 절에서 사용
	SELECT * FROM users
	WHERE age > (SELECT AVG(age) FROM users);

	-- FROM 절에서 사용
	SELECT * FROM (
	  SELECT name, age FROM users WHERE age > 25
	) AS young_users;

	-- IN 사용
	SELECT * FROM posts
	WHERE user_id IN (SELECT id FROM users WHERE age > 30);
	```

	**TypeORM vs Raw SQL 비교**
	```typescript
	// TypeORM
	const users = await this.userRepository.find({
	  where: { age: MoreThan(25) },
	  order: { createdAt: 'DESC' },
	  take: 10,
	});

	// Raw SQL
	const users = await this.userRepository.query(
	  'SELECT * FROM users WHERE age > ? ORDER BY created_at DESC LIMIT 10',
	  [25]
	);
	```

**핵심 개념**:

**TypeORM의 핵심 가치**
- **타입 안정성**: 컴파일 타임에 데이터베이스 관련 에러 검출
- **생산성**: SQL을 직접 작성하지 않고 TypeScript 코드로 데이터 조작
- **유지보수성**: 데이터베이스 변경 시 코드 수정 최소화
- **추상화**: 데이터베이스 종류에 관계없이 동일한 코드 사용 가능

**관계 설정의 원칙**
- `@JoinColumn()`은 외래 키를 가지는 쪽(Many 쪽)에 설정
- `@JoinTable()`은 Many-to-Many에서 한쪽에만 설정
- `cascade` 옵션으로 연관 엔티티 자동 관리
- `onDelete` 옵션으로 참조 무결성 보장

**ORM vs Raw SQL**
- **ORM 장점**: 타입 안정성, 데이터베이스 독립성, 유지보수 용이
- **Raw SQL 장점**: 복잡한 쿼리 최적화, 성능 튜닝 가능
- **결론**: 일반적인 CRUD는 ORM, 복잡한 쿼리는 QueryBuilder나 Raw SQL 혼용

**예제 코드**:
```typescript
// 완전한 TypeORM 예제 - User와 Post 관계

// 1. User Entity
@Entity('users')
export class User {
  @PrimaryGeneratedColumn()
  id: number;

  @Column({ unique: true })
  email: string;

  @Column()
  name: string;

  @CreateDateColumn()
  createdAt: Date;

  @UpdateDateColumn()
  updatedAt: Date;

  // 한 명의 User는 여러 Post를 가짐
  @OneToMany(() => Post, post => post.user, { cascade: true })
  posts: Post[];
}

// 2. Post Entity
@Entity('posts')
export class Post {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  title: string;

  @Column('text')
  content: string;

  @Column({ default: 0 })
  views: number;

  @CreateDateColumn()
  createdAt: Date;

  // 여러 Post는 한 명의 User에 속함
  @ManyToOne(() => User, user => user.posts, { onDelete: 'CASCADE' })
  @JoinColumn({ name: 'user_id' })
  user: User;

  @Column({ name: 'user_id' })
  userId: number;
}

// 3. Service에서 사용
@Injectable()
export class PostService {
  constructor(
    @InjectRepository(Post)
    private postRepository: Repository<Post>,
    @InjectRepository(User)
    private userRepository: Repository<User>,
  ) {}

  // 게시글 생성 (관계 설정)
  async create(userId: number, createPostDto: CreatePostDto): Promise<Post> {
    const user = await this.userRepository.findOne({ where: { id: userId } });

    if (!user) {
      throw new NotFoundException('User not found');
    }

    const post = this.postRepository.create({
      ...createPostDto,
      user, // 관계 설정
    });

    return this.postRepository.save(post);
  }

  // 사용자의 모든 게시글 조회
  async findByUser(userId: number): Promise<Post[]> {
    return this.postRepository.find({
      where: { userId },
      relations: ['user'],
      order: { createdAt: 'DESC' },
    });
  }

  // 게시글과 작성자 정보 함께 조회 (JOIN)
  async findWithAuthor(postId: number): Promise<Post> {
    return this.postRepository.findOne({
      where: { id: postId },
      relations: ['user'],
    });
  }

  // QueryBuilder 사용 (복잡한 쿼리)
  async findPopularPosts(): Promise<Post[]> {
    return this.postRepository
      .createQueryBuilder('post')
      .leftJoinAndSelect('post.user', 'user')
      .where('post.views > :views', { views: 100 })
      .orderBy('post.views', 'DESC')
      .take(10)
      .getMany();
  }

  // Raw SQL 사용 (최적화된 쿼리)
  async getPostStats() {
    return this.postRepository.query(`
      SELECT
        u.name as author,
        COUNT(p.id) as post_count,
        AVG(p.views) as avg_views
      FROM users u
      LEFT JOIN posts p ON u.id = p.user_id
      GROUP BY u.id, u.name
      ORDER BY post_count DESC
    `);
  }
}
```

**결과**:
- TypeORM으로 객체 지향적으로 데이터베이스 조작 가능
- 관계 설정으로 복잡한 데이터 구조를 명확하게 표현
- Repository 패턴으로 데이터 접근 계층 분리
- SQL 지식과 ORM을 함께 활용하여 최적의 성능과 생산성 확보
- TypeORM Model Generator로 레거시 DB 마이그레이션 간편화

## 💡 인사이트 & 깨달음

- **ORM은 SQL을 대체하는 것이 아니라 보완하는 도구**: TypeORM을 사용하면서도 SQL 개념을 정확히 이해해야 효율적인 쿼리 작성 가능
- **관계 설정의 양방향성**: User → Post, Post → User 양방향으로 설정하면 어느 쪽에서든 접근 가능하지만, 순환 참조 주의 필요
- **cascade 옵션의 위험성**: 편리하지만 의도치 않은 데이터 삭제 발생 가능. 운영 환경에서는 신중하게 사용해야 함
- **N+1 문제**: 관계 데이터 조회 시 `relations` 옵션이나 `leftJoinAndSelect`를 사용하지 않으면 N+1 쿼리 발생
- **synchronize: false in production**: 개발 환경에서만 `synchronize: true` 사용. 운영에서는 마이그레이션으로 스키마 관리
- **TypeORM Model Generator의 실용성**: 레거시 시스템을 NestJS로 전환할 때 초기 작업 시간을 획기적으로 단축
- **QueryBuilder의 강력함**: 복잡한 조건문, 서브쿼리, 동적 쿼리 작성 시 Repository 메서드보다 QueryBuilder가 더 유연
- **타입 안정성의 진가**: Entity 수정 시 관련된 모든 코드에서 컴파일 에러 발생. 런타임 에러를 사전에 방지
