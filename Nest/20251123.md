## 📝 배운 내용

#### 상세 내용

- **NestJS Module 기본 개념**

	**Module이란?**
	- NestJS 애플리케이션의 기본 구성 단위
	- 관련된 기능들을 하나로 묶어서 관리하는 컨테이너
	- `@Module()` 데코레이터로 정의
	- 모든 NestJS 앱은 최소 하나의 루트 모듈(AppModule)을 가짐

	**Module의 구조**
	```typescript
	@Module({
	  imports: [],      // 다른 모듈 가져오기
	  controllers: [],  // 이 모듈의 컨트롤러
	  providers: [],    // 이 모듈의 서비스/프로바이더
	  exports: [],      // 다른 모듈에서 사용할 수 있도록 내보내기
	})
	export class SomeModule {}
	```

	**Module의 4가지 속성**

	| 속성 | 역할 | 언제 사용? |
	|------|------|-----------|
	| `imports` | 다른 모듈 가져오기 | 외부 모듈의 기능이 필요할 때 |
	| `controllers` | HTTP 요청 처리 | API 엔드포인트가 필요할 때 |
	| `providers` | 의존성 주입 대상 | Service, Repository 등 주입 가능한 클래스 |
	| `exports` | 외부 노출 | 이 모듈의 provider를 다른 모듈에서 사용하게 할 때 |

- **Providers (프로바이더) - 언제 추가하나?**

	**Providers란?**
	- 의존성 주입(DI)이 가능한 클래스
	- `@Injectable()` 데코레이터가 붙은 클래스
	- Service, Repository, Factory, Helper 등

	**Providers에 추가하는 경우**
	```typescript
	// ✅ 이런 것들을 providers에 추가
	@Module({
	  providers: [
	    UserService,           // 서비스
	    EmailService,          // 이메일 발송 서비스
	    LoggerService,         // 로깅 서비스
	    UserRepository,        // 커스텀 레포지토리
	    PasswordHasher,        // 헬퍼 클래스
	  ],
	})
	```

	**Provider 등록 규칙**
	1. **이 모듈 내부에서 생성하고 사용하는 클래스**
	2. **`@Injectable()` 데코레이터가 붙은 클래스**
	3. **다른 곳에 주입(inject)하고 싶은 클래스**

	**예제: UserModule**
	```typescript
	// user.service.ts
	@Injectable()
	export class UserService {
	  findAll() {
	    return ['user1', 'user2'];
	  }
	}

	// user.controller.ts
	@Controller('users')
	export class UserController {
	  constructor(
	    private userService: UserService // ← 이것을 주입받으려면
	  ) {}
	}

	// user.module.ts
	@Module({
	  controllers: [UserController],
	  providers: [UserService], // ← 여기에 등록해야 함!
	})
	export class UserModule {}
	```

	**왜 providers에 등록해야 하나?**
	- NestJS의 DI 컨테이너가 인스턴스를 생성하고 관리
	- 등록하지 않으면 `Nest can't resolve dependencies` 에러 발생
	- 싱글톤으로 관리되어 메모리 효율적

	**Provider 등록 안 해도 되는 경우**
	```typescript
	// ❌ 이런 것들은 providers에 안 넣음
	- DTO 클래스 (CreateUserDto, UpdateUserDto)
	- Entity 클래스 (User, Post)
	- Interface (UserInterface)
	- Enum, Constant
	```

- **Imports (임포트) - 언제 추가하나?**

	**Imports란?**
	- 다른 모듈을 현재 모듈에 가져오는 것
	- 가져온 모듈이 `exports`한 provider를 사용할 수 있음

	**Imports에 추가하는 경우**

	**1. 다른 기능 모듈을 사용할 때**
	```typescript
	// auth.module.ts
	@Module({
	  providers: [AuthService],
	  exports: [AuthService], // ← 외부에 노출
	})
	export class AuthModule {}

	// user.module.ts
	@Module({
	  imports: [AuthModule], // ← AuthModule을 가져옴
	  providers: [UserService],
	  controllers: [UserController],
	})
	export class UserModule {}

	// user.service.ts
	@Injectable()
	export class UserService {
	  constructor(
	    private authService: AuthService // ← AuthModule이 export한 것 사용 가능
	  ) {}
	}
	```

	**2. TypeORM 모듈을 사용할 때**
	```typescript
	@Module({
	  imports: [
	    TypeOrmModule.forFeature([User, Post]), // ← Repository 사용하려면 필수
	  ],
	  providers: [UserService],
	})
	export class UserModule {}

	@Injectable()
	export class UserService {
	  constructor(
	    @InjectRepository(User)
	    private userRepository: Repository<User>, // ← 주입 가능
	  ) {}
	}
	```

	**3. 전역 설정 모듈을 사용할 때**
	```typescript
	@Module({
	  imports: [
	    ConfigModule.forRoot(),  // 환경변수 모듈
	    TypeOrmModule.forRoot(), // DB 연결 모듈
	  ],
	})
	export class AppModule {}
	```

	**Imports vs Providers 차이**

	| 구분 | Imports | Providers |
	|------|---------|-----------|
	| **대상** | 다른 모듈 | 서비스/클래스 |
	| **목적** | 외부 모듈의 기능 가져오기 | 이 모듈 내부에서 사용할 클래스 등록 |
	| **예시** | `imports: [AuthModule]` | `providers: [UserService]` |

- **Exports (익스포트) - 언제 추가하나?**

	**Exports란?**
	- 이 모듈의 provider를 다른 모듈에서 사용할 수 있도록 내보내기
	- exports에 추가하지 않으면 외부에서 사용 불가

	**Exports에 추가하는 경우**
	```typescript
	// email.module.ts
	@Module({
	  providers: [EmailService],
	  exports: [EmailService], // ← 다른 모듈에서 사용할 수 있도록 노출
	})
	export class EmailModule {}

	// user.module.ts
	@Module({
	  imports: [EmailModule], // ← EmailModule 가져옴
	  providers: [UserService],
	})
	export class UserModule {}

	// user.service.ts
	@Injectable()
	export class UserService {
	  constructor(
	    private emailService: EmailService // ← 사용 가능!
	  ) {}

	  async register(user: User) {
	    // 회원가입 로직
	    await this.emailService.sendWelcomeEmail(user.email);
	  }
	}
	```

	**Export 안 했을 때 에러**
	```typescript
	// email.module.ts
	@Module({
	  providers: [EmailService],
	  // exports: [EmailService], ← 주석 처리
	})
	export class EmailModule {}

	// user.service.ts에서 EmailService 주입 시도
	// ❌ Error: Nest can't resolve dependencies of the UserService (?, EmailService)
	// EmailService가 export되지 않아서 외부에서 사용 불가
	```

	**Export 규칙**
	1. **providers에 있는 것만 export 가능**
	2. **다른 모듈에서 사용할 것만 export**
	3. **모듈 자체도 re-export 가능**

	**모듈 Re-export**
	```typescript
	// common.module.ts - 여러 모듈을 묶어서 재배포
	@Module({
	  imports: [EmailModule, LoggerModule, CacheModule],
	  exports: [EmailModule, LoggerModule, CacheModule], // 모듈 그대로 재배포
	})
	export class CommonModule {}

	// user.module.ts
	@Module({
	  imports: [CommonModule], // ← 하나만 import하면 3개 모듈 모두 사용 가능
	  providers: [UserService],
	})
	export class UserModule {}
	```

- **실전 예제: Module, Imports, Providers, Exports 완벽 이해**

	**시나리오: 사용자 등록 시 이메일 발송**

	**1단계: 각 모듈 분리**

	```typescript
	// ========================================
	// 1. EmailModule - 이메일 발송 기능
	// ========================================

	// email.service.ts
	@Injectable()
	export class EmailService {
	  sendWelcomeEmail(email: string) {
	    console.log(`Welcome email sent to ${email}`);
	  }
	}

	// email.module.ts
	@Module({
	  providers: [EmailService],  // ← EmailService를 DI 컨테이너에 등록
	  exports: [EmailService],    // ← 다른 모듈에서 사용할 수 있도록 노출
	})
	export class EmailModule {}
	```

	```typescript
	// ========================================
	// 2. UserModule - 사용자 관리 기능
	// ========================================

	// user.entity.ts
	@Entity()
	export class User {
	  @PrimaryGeneratedColumn()
	  id: number;

	  @Column()
	  email: string;

	  @Column()
	  name: string;
	}

	// user.service.ts
	@Injectable()
	export class UserService {
	  constructor(
	    @InjectRepository(User)
	    private userRepository: Repository<User>,
	    private emailService: EmailService, // ← EmailModule에서 가져옴
	  ) {}

	  async create(createUserDto: CreateUserDto) {
	    const user = this.userRepository.create(createUserDto);
	    await this.userRepository.save(user);

	    // 이메일 발송
	    await this.emailService.sendWelcomeEmail(user.email);

	    return user;
	  }
	}

	// user.controller.ts
	@Controller('users')
	export class UserController {
	  constructor(private userService: UserService) {}

	  @Post()
	  create(@Body() createUserDto: CreateUserDto) {
	    return this.userService.create(createUserDto);
	  }
	}

	// user.module.ts
	@Module({
	  imports: [
	    TypeOrmModule.forFeature([User]), // ← User Repository 사용하려면 필수
	    EmailModule,                      // ← EmailService 사용하려면 필수
	  ],
	  controllers: [UserController],      // ← HTTP 요청 처리
	  providers: [UserService],           // ← DI 컨테이너에 등록
	  exports: [UserService],             // ← 다른 모듈에서 UserService 사용 가능
	})
	export class UserModule {}
	```

	```typescript
	// ========================================
	// 3. AppModule - 루트 모듈
	// ========================================

	// app.module.ts
	@Module({
	  imports: [
	    ConfigModule.forRoot({ isGlobal: true }),
	    TypeOrmModule.forRoot({
	      type: 'mysql',
	      host: 'localhost',
	      port: 3306,
	      username: 'root',
	      password: 'password',
	      database: 'test_db',
	      entities: [User],
	      synchronize: false,
	    }),
	    UserModule,   // ← UserModule 전체를 가져옴
	    EmailModule,  // ← EmailModule 전체를 가져옴 (선택사항)
	  ],
	})
	export class AppModule {}
	```

	**2단계: 의존성 주입 흐름 분석**

	```
	UserController
	      ↓ (의존)
	  UserService
	      ↓ (의존)
	  ┌─────────────┬─────────────┐
	  ↓             ↓             ↓
	UserRepository  EmailService  ...
	  ↓                ↓
	TypeOrmModule  EmailModule
	```

	**3단계: 각 모듈 설정 이유**

	**UserModule의 imports**
	```typescript
	imports: [
	  TypeOrmModule.forFeature([User]), // UserRepository를 주입받으려면
	  EmailModule,                      // EmailService를 주입받으려면
	]
	```

	**UserModule의 providers**
	```typescript
	providers: [UserService], // UserService를 DI 컨테이너에 등록
	                          // → UserController에 주입 가능
	```

	**UserModule의 exports**
	```typescript
	exports: [UserService], // 다른 모듈(예: AdminModule)에서
	                        // UserService를 사용할 수 있게 함
	```

	**EmailModule의 exports**
	```typescript
	exports: [EmailService], // UserModule에서 EmailService를
	                         // 사용할 수 있게 함
	```

- **헷갈리는 상황별 해결 가이드**

	**상황 1: "Nest can't resolve dependencies" 에러**
	```typescript
	// ❌ 에러 발생
	@Module({
	  controllers: [UserController],
	  // providers: [UserService], ← 누락!
	})
	export class UserModule {}

	// ✅ 해결
	@Module({
	  controllers: [UserController],
	  providers: [UserService], // ← 추가
	})
	export class UserModule {}
	```

	**상황 2: 다른 모듈의 서비스를 사용하고 싶을 때**
	```typescript
	// ❌ 잘못된 방법
	@Module({
	  providers: [UserService, EmailService], // EmailService는 EmailModule 것!
	})
	export class UserModule {}

	// ✅ 올바른 방법
	@Module({
	  imports: [EmailModule],  // EmailModule을 가져옴
	  providers: [UserService], // UserService만 등록
	})
	export class UserModule {}
	```

	**상황 3: TypeORM Repository 사용하고 싶을 때**
	```typescript
	// ❌ 잘못된 방법
	@Module({
	  providers: [UserService],
	})
	export class UserModule {}

	// ✅ 올바른 방법
	@Module({
	  imports: [
	    TypeOrmModule.forFeature([User]), // ← Repository 등록
	  ],
	  providers: [UserService],
	})
	export class UserModule {}
	```

	**상황 4: 전역으로 사용하고 싶을 때**
	```typescript
	// config.module.ts - 모든 곳에서 ConfigService 사용하고 싶을 때
	@Global() // ← 전역 모듈로 설정
	@Module({
	  providers: [ConfigService],
	  exports: [ConfigService],
	})
	export class ConfigModule {}

	// app.module.ts
	@Module({
	  imports: [ConfigModule], // 한 번만 import
	})
	export class AppModule {}

	// 이제 다른 모듈에서 imports 없이도 ConfigService 사용 가능
	```

**핵심 개념**:

**Module 설정 4단계 체크리스트**

```typescript
@Module({
  // 1. imports - "무엇을 가져올까?"
  imports: [
    // ✅ 다른 모듈이 필요하면 여기
    // ✅ TypeORM Repository 필요하면 forFeature
    // ✅ 외부 라이브러리 모듈 (ConfigModule 등)
  ],

  // 2. controllers - "어떤 API를 만들까?"
  controllers: [
    // ✅ HTTP 엔드포인트가 필요하면 여기
  ],

  // 3. providers - "무엇을 주입 가능하게 만들까?"
  providers: [
    // ✅ @Injectable() 붙은 클래스
    // ✅ 이 모듈 내부에서 생성하고 관리하는 서비스
  ],

  // 4. exports - "무엇을 외부에 공유할까?"
  exports: [
    // ✅ 다른 모듈에서 사용하게 할 provider
    // ✅ 다시 내보낼(re-export) 모듈
  ],
})
```

**의존성 주입 3단계 원칙**

1. **등록 (Register)**: `providers`에 추가
2. **주입 (Inject)**: `constructor`에서 받기
3. **공유 (Share)**: `exports`로 외부 노출

**Imports vs Providers 결정 트리**

```
필요한 것이 있는가?
  ├─ 다른 모듈의 기능인가?
  │   └─ YES → imports에 추가
  └─ 이 모듈에서 만든 클래스인가?
      └─ YES → providers에 추가
```

**Exports 결정 기준**

```
이 provider를 외부에서 사용하는가?
  ├─ YES → exports에 추가
  └─ NO → exports에 추가 안 함 (내부 전용)
```

**예제 코드**:
```typescript
// ============================================
// 완전한 예제: 게시판 시스템
// ============================================

// ========== 1. CommonModule (공통 기능) ==========
@Injectable()
export class LoggerService {
  log(message: string) {
    console.log(`[LOG] ${message}`);
  }
}

@Global() // 전역 모듈
@Module({
  providers: [LoggerService],
  exports: [LoggerService],
})
export class CommonModule {}

// ========== 2. EmailModule (이메일 발송) ==========
@Injectable()
export class EmailService {
  constructor(private logger: LoggerService) {} // Global이라 imports 없이 주입 가능

  sendEmail(to: string, subject: string) {
    this.logger.log(`Email sent to ${to}: ${subject}`);
  }
}

@Module({
  providers: [EmailService],
  exports: [EmailService], // ← 외부에서 사용 가능하도록
})
export class EmailModule {}

// ========== 3. UserModule (사용자 관리) ==========
@Entity()
export class User {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  email: string;

  @Column()
  name: string;
}

@Injectable()
export class UserService {
  constructor(
    @InjectRepository(User)
    private userRepository: Repository<User>,
    private emailService: EmailService,  // EmailModule에서 가져옴
    private logger: LoggerService,       // Global이라 자동 주입
  ) {}

  async create(email: string, name: string) {
    this.logger.log(`Creating user: ${email}`);

    const user = this.userRepository.create({ email, name });
    await this.userRepository.save(user);

    await this.emailService.sendEmail(email, 'Welcome!');

    return user;
  }

  async findAll() {
    return this.userRepository.find();
  }
}

@Controller('users')
export class UserController {
  constructor(private userService: UserService) {}

  @Post()
  create(@Body() createUserDto: { email: string; name: string }) {
    return this.userService.create(createUserDto.email, createUserDto.name);
  }

  @Get()
  findAll() {
    return this.userService.findAll();
  }
}

@Module({
  imports: [
    TypeOrmModule.forFeature([User]), // User Repository 사용
    EmailModule,                      // EmailService 사용
  ],
  controllers: [UserController],
  providers: [UserService],
  exports: [UserService],             // PostModule에서 사용할 수 있도록
})
export class UserModule {}

// ========== 4. PostModule (게시글 관리) ==========
@Entity()
export class Post {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  title: string;

  @Column()
  content: string;

  @ManyToOne(() => User)
  author: User;
}

@Injectable()
export class PostService {
  constructor(
    @InjectRepository(Post)
    private postRepository: Repository<Post>,
    private userService: UserService, // UserModule에서 가져옴
    private logger: LoggerService,    // Global
  ) {}

  async create(title: string, content: string, userId: number) {
    this.logger.log(`Creating post: ${title}`);

    // UserService 사용
    const users = await this.userService.findAll();
    const author = users.find(u => u.id === userId);

    const post = this.postRepository.create({ title, content, author });
    return this.postRepository.save(post);
  }
}

@Controller('posts')
export class PostController {
  constructor(private postService: PostService) {}

  @Post()
  create(@Body() createPostDto: { title: string; content: string; userId: number }) {
    return this.postService.create(
      createPostDto.title,
      createPostDto.content,
      createPostDto.userId,
    );
  }
}

@Module({
  imports: [
    TypeOrmModule.forFeature([Post]), // Post Repository
    UserModule,                       // UserService 사용
  ],
  controllers: [PostController],
  providers: [PostService],
})
export class PostModule {}

// ========== 5. AppModule (루트 모듈) ==========
@Module({
  imports: [
    ConfigModule.forRoot({ isGlobal: true }),
    TypeOrmModule.forRoot({
      type: 'mysql',
      host: 'localhost',
      port: 3306,
      username: 'root',
      password: 'password',
      database: 'test_db',
      entities: [User, Post],
      synchronize: false,
    }),
    CommonModule, // 전역 모듈
    EmailModule,
    UserModule,
    PostModule,
  ],
})
export class AppModule {}
```

**의존성 주입 흐름 정리**
```
AppModule
  ├─ CommonModule (Global)
  │   └─ LoggerService ───────────┐
  │                               ↓ (전역 주입)
  ├─ EmailModule                  ↓
  │   └─ EmailService ──────┐     ↓
  │                         ↓     ↓
  ├─ UserModule             ↓     ↓
  │   ├─ UserRepository     ↓     ↓
  │   └─ UserService ←──────┴─────┤
  │                         ↓     ↓
  └─ PostModule             ↓     ↓
      ├─ PostRepository     ↓     ↓
      └─ PostService ←──────┴─────┘
```

**결과**:
- **명확한 모듈 분리**: 각 모듈이 자신의 책임만 가짐
- **재사용성**: EmailService, UserService를 여러 모듈에서 공유
- **유지보수성**: 모듈별로 독립적으로 수정 가능
- **테스트 용이성**: 각 모듈을 독립적으로 테스트 가능
- **전역 모듈**: LoggerService는 @Global()로 어디서든 사용 가능

## 💡 인사이트 & 깨달음

- **imports는 "모듈"을, providers는 "클래스"를 등록**: 이 차이를 명확히 하면 혼란이 사라짐
- **exports는 "공유의 의도"를 표현**: 외부에서 사용하게 할 것만 export하면 캡슐화 유지
- **TypeORM Repository는 특별**: `forFeature([Entity])`로 imports에 추가해야 `@InjectRepository()` 사용 가능
- **@Global() 남용 금지**: 편하지만 의존성이 암묵적으로 되어 추적이 어려움. 필요한 경우만 사용
- **순환 참조 주의**: UserModule이 PostModule을 import하고, PostModule이 UserModule을 import하면 에러. `forwardRef()` 사용 필요
- **Module은 기능 단위로 분리**: User, Post, Auth처럼 도메인별로 나누면 관리가 편함
- **Re-export 패턴**: CommonModule처럼 여러 모듈을 묶어서 재배포하면 imports가 깔끔해짐
- **providers 배열 순서는 무관**: NestJS가 의존성 그래프를 자동으로 해결
