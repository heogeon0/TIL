- **인증 (Authentication) vs 인가 (Authorization)**

	**인증 (Authentication)이란?**
	- "너는 누구니?" - 사용자의 신원을 확인하는 과정
	- 로그인을 통해 사용자가 본인임을 증명
	- 예: 이메일/비밀번호, OAuth, JWT 토큰

	**인가 (Authorization)란?**
	- "너는 이걸 할 수 있니?" - 사용자의 권한을 확인하는 과정
	- 인증된 사용자가 특정 리소스에 접근할 수 있는지 판단
	- 예: 관리자만 사용자 삭제 가능, 작성자만 게시글 수정 가능

	**차이점**

	| 구분 | 인증 (Authentication) | 인가 (Authorization) |
	|------|---------------------|---------------------|
	| **질문** | 누구인가? | 무엇을 할 수 있는가? |
	| **시점** | 로그인 시 | 리소스 접근 시 |
	| **예시** | 비밀번호 확인 | 역할 확인 (admin, user) |
	| **실패 시** | 401 Unauthorized | 403 Forbidden |

	```typescript
	// 인증 예시
	@Post('login')
	async login(@Body() loginDto: LoginDto) {
	  const user = await this.authService.validateUser(loginDto);
	  if (!user) {
	    throw new UnauthorizedException('잘못된 인증 정보'); // 401
	  }
	  return this.authService.login(user);
	}

	// 인가 예시
	@Delete(':id')
	@UseGuards(AuthGuard, RolesGuard)
	@Roles('admin') // 관리자만 가능
	async deleteUser(@Param('id') id: number) {
	  return this.userService.delete(id); // admin 아니면 403
	}
	```

- **NestJS Guard (가드)**

	**Guard란?**
	- Request Lifecycle에서 컨트롤러 실행 전에 실행되는 계층
	- 요청을 통과시킬지 막을지 결정 (true/false 반환)
	- 주로 인증/인가에 사용

	**Guard의 특징**
	- `CanActivate` 인터페이스를 구현
	- `canActivate()` 메서드가 `true`면 통과, `false`면 403 Forbidden
	- ExecutionContext를 통해 요청 정보 접근

	**기본 Guard 구조**

	```typescript
	import { Injectable, CanActivate, ExecutionContext } from '@nestjs/common';

	@Injectable()
	export class AuthGuard implements CanActivate {
	  canActivate(context: ExecutionContext): boolean {
	    const request = context.switchToHttp().getRequest();

	    // 인증 로직
	    return !!request.user; // user가 있으면 통과
	  }
	}
	```

	**Guard 적용 방법**

	**1. 메서드 레벨**
	```typescript
	@Get('profile')
	@UseGuards(AuthGuard)
	getProfile(@Request() req) {
	  return req.user;
	}
	```

	**2. 컨트롤러 레벨**
	```typescript
	@Controller('users')
	@UseGuards(AuthGuard)
	export class UserController {
	  // 모든 메서드에 AuthGuard 적용
	}
	```

	**3. 전역 레벨**
	```typescript
	// main.ts
	app.useGlobalGuards(new AuthGuard());

	// 또는 Module에서 DI
	@Module({
	  providers: [
	    {
	      provide: APP_GUARD,
	      useClass: AuthGuard,
	    },
	  ],
	})
	```

	**JWT 인증 Guard 예제**

	```typescript
	import { Injectable, ExecutionContext, UnauthorizedException } from '@nestjs/common';
	import { JwtService } from '@nestjs/jwt';

	@Injectable()
	export class JwtAuthGuard implements CanActivate {
	  constructor(private jwtService: JwtService) {}

	  canActivate(context: ExecutionContext): boolean {
	    const request = context.switchToHttp().getRequest();
	    const token = this.extractTokenFromHeader(request);

	    if (!token) {
	      throw new UnauthorizedException('토큰이 없습니다');
	    }

	    try {
	      const payload = this.jwtService.verify(token);
	      request.user = payload; // 검증된 사용자 정보를 request에 추가
	      return true;
	    } catch {
	      throw new UnauthorizedException('유효하지 않은 토큰');
	    }
	  }

	  private extractTokenFromHeader(request: any): string | undefined {
	    const [type, token] = request.headers.authorization?.split(' ') ?? [];
	    return type === 'Bearer' ? token : undefined;
	  }
	}
	```

	**역할 기반 Guard (Role-Based Guard)**

	```typescript
	// roles.decorator.ts
	import { SetMetadata } from '@nestjs/common';

	export const ROLES_KEY = 'roles';
	export const Roles = (...roles: string[]) => SetMetadata(ROLES_KEY, roles);

	// roles.guard.ts
	import { Injectable, CanActivate, ExecutionContext } from '@nestjs/common';
	import { Reflector } from '@nestjs/core';
	import { ROLES_KEY } from './roles.decorator';

	@Injectable()
	export class RolesGuard implements CanActivate {
	  constructor(private reflector: Reflector) {}

	  canActivate(context: ExecutionContext): boolean {
	    const requiredRoles = this.reflector.getAllAndOverride<string[]>(ROLES_KEY, [
	      context.getHandler(),
	      context.getClass(),
	    ]);

	    if (!requiredRoles) {
	      return true; // 역할 제한 없음
	    }

	    const request = context.switchToHttp().getRequest();
	    const user = request.user;

	    return requiredRoles.some((role) => user.roles?.includes(role));
	  }
	}

	// 사용
	@Delete(':id')
	@UseGuards(JwtAuthGuard, RolesGuard)
	@Roles('admin')
	deleteUser(@Param('id') id: number) {
	  return this.userService.delete(id);
	}
	```

	**Passport란?**

	- 500개 이상의 인증 전략(Strategy) 지원

	**Passport 전략 (Strategy)**
	- Local Strategy: 이메일/비밀번호 로그인
	- JWT Strategy: JWT 토큰 검증
	- OAuth Strategy: 소셜 로그인 (Google, Facebook 등)

- **Local Strategy (이메일/비밀번호 인증)**

	**1단계: AuthService 생성**

	```typescript
	// auth.service.ts
	import { Injectable, UnauthorizedException } from '@nestjs/common';
	import { UserService } from '../user/user.service';
	import { JwtService } from '@nestjs/jwt';
	import * as bcrypt from 'bcrypt';

	@Injectable()
	export class AuthService {
	  constructor(
	    private userService: UserService,
	    private jwtService: JwtService,
	  ) {}

	  // 사용자 검증
	  async validateUser(email: string, password: string): Promise<any> {
	    const user = await this.userService.findByEmail(email);

	    if (!user) {
	      throw new UnauthorizedException('사용자를 찾을 수 없습니다');
	    }

	    const isPasswordValid = await bcrypt.compare(password, user.password);

	    if (!isPasswordValid) {
	      throw new UnauthorizedException('비밀번호가 일치하지 않습니다');
	    }

	    const { password: _, ...result } = user;
	    return result;
	  }

	  // 로그인 (JWT 토큰 발급)
	  async login(user: any) {
	    const payload = { email: user.email, sub: user.id, roles: user.roles };

	    return {
	      access_token: this.jwtService.sign(payload),
	      user: {
	        id: user.id,
	        email: user.email,
	        name: user.name,
	      },
	    };
	  }

	  // 회원가입
	  async register(email: string, password: string, name: string) {
	    const hashedPassword = await bcrypt.hash(password, 10);

	    return this.userService.create({
	      email,
	      password: hashedPassword,
	      name,
	    });
	  }
	}
	```

	**2단계: Local Strategy 구현**

	```bash
	npm install passport-local
	npm install -D @types/passport-local
	```

	```typescript
	// strategies/local.strategy.ts
	import { Strategy } from 'passport-local';
	import { PassportStrategy } from '@nestjs/passport';
	import { Injectable, UnauthorizedException } from '@nestjs/common';
	import { AuthService } from '../auth.service';

	@Injectable()
	export class LocalStrategy extends PassportStrategy(Strategy) {
	  constructor(private authService: AuthService) {
	    super({
	      usernameField: 'email', // 기본은 'username', 이메일로 변경
	      passwordField: 'password',
	    });
	  }

	  async validate(email: string, password: string): Promise<any> {
	    const user = await this.authService.validateUser(email, password);

	    if (!user) {
	      throw new UnauthorizedException();
	    }

	    return user;
	  }
	}
	```

	```typescript

	import { Controller, Post, UseGuards, Request, Body } from '@nestjs/common';
	import { AuthService } from './auth.service';
	import { LocalAuthGuard } from './guards/local-auth.guard';

	@Controller('auth')
	export class AuthController {
	  constructor(private authService: AuthService) {}

	  @Post('register')
	  async register(@Body() registerDto: { email: string; password: string; name: string }) {
	    return this.authService.register(
	      registerDto.email,
	      registerDto.password,
	      registerDto.name,
	    );
	  }

	  @UseGuards(LocalAuthGuard)
	  @Post('login')
	  async login(@Request() req) {
	    // LocalAuthGuard가 validate를 실행하고 user를 req에 추가
	```

- **JWT Strategy (토큰 인증)**

	**1단계: JWT Strategy 구현**

	```typescript
	// strategies/jwt.strategy.ts
	import { ExtractJwt, Strategy } from 'passport-jwt';
	import { PassportStrategy } from '@nestjs/passport';
	import { Injectable } from '@nestjs/common';

	@Injectable()
	export class JwtStrategy extends PassportStrategy(Strategy) {
	  constructor() {
	    super({
	      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
	      ignoreExpiration: false,
	      secretOrKey: process.env.JWT_SECRET || 'your-secret-key',
	    });
	  }

	  async validate(payload: any) {
	    // payload는 JWT 토큰의 내용
	    return {
	      id: payload.sub,
	      email: payload.email,
	      roles: payload.roles,
	    };
	  }
	}
	```

- **전체 인증 흐름 정리**

	**회원가입 → 로그인 → 인증된 요청**

	**1. 회원가입**
	```bash
	POST /auth/register
	{
	  "email": "user@example.com",
	  "password": "password123",
	  "name": "John Doe"
	}

	# Response
	{
	  "id": 1,
	  "email": "user@example.com",
	  "name": "John Doe"
	}
	```

	**2. 로그인**
	```bash
	POST /auth/login
	{
	  "email": "user@example.com",
	  "password": "password123"
	}

	# Response
	{
	  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
	  "user": {
	    "id": 1,
	    "email": "user@example.com",
	    "name": "John Doe"
	  }
	}
	```

	**3. 인증된 요청**
	```bash
	GET /users/profile
	Headers:
	  Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

	# Response
	{
	  "id": 1,
	  "email": "user@example.com",
	  "roles": ["user"]
	}
	```

	**인증 흐름 다이어그램**

	```
	[Client]
	   │
	   │ POST /auth/login (email, password)
	   ↓
	[LocalAuthGuard]
	   │
	   │ LocalStrategy.validate() 실행
	   ↓
	[AuthService.validateUser()]
	   │
	   │ DB에서 사용자 조회
	   │ bcrypt로 비밀번호 비교
	   ↓
	[AuthService.login()]
	   │
	   │ JWT 토큰 생성
	   ↓
	[Client] ← access_token 반환
	   │
	   │ GET /users/profile (Header: Bearer token)
	   ↓
	[JwtAuthGuard]
	   │
	   │ JwtStrategy.validate() 실행
	   │ 토큰 검증 후 payload 반환
	   ↓
	[Controller]
	   │
	   │ req.user에 접근 가능
	   ↓
	[Response]
	```

**핵심 개념**:

**인증의 3가지 방식**

1. **Session 기반 인증**
   - 서버에 세션 저장
   - 쿠키로 세션 ID 전달
   - 서버 메모리 사용 (확장성 문제)

2. **Token 기반 인증 (JWT)**
   - 서버는 토큰만 발급
   - 클라이언트가 토큰 저장 및 전송
   - Stateless (서버에 상태 저장 안 함)
   - 확장성 좋음

3. **OAuth 2.0**
   - 소셜 로그인 (Google, Facebook 등)
   - 제3자 인증 위임

**Guard vs Middleware 차이**

| 구분 | Middleware | Guard |
|------|-----------|-------|
| **실행 시점** | 라우트 핸들러 전 | 라우트 핸들러 직전 |
| **반환 값** | void (next() 호출) | boolean (통과 여부) |
| **목적** | 요청 로깅, 파싱 등 | 인증/인가 |
| **Context** | Request/Response | ExecutionContext |

**예제 코드**:
```typescript
// ============================================
// 완전한 예제: JWT 인증 시스템
// ============================================

// ========== 1. User Entity ==========
@Entity('users')
export class User {
  @PrimaryGeneratedColumn()
  id: number;

  @Column({ unique: true })
  email: string;

  @Column()
  password: string;

  @Column()
  name: string;

  @Column({ type: 'simple-array', default: 'user' })
  roles: string[];
}

// ========== 2. Auth Service ==========
@Injectable()
export class AuthService {
  constructor(
    @InjectRepository(User)
    private userRepository: Repository<User>,
    private jwtService: JwtService,
  ) {}

  async validateUser(email: string, password: string) {
    const user = await this.userRepository.findOne({ where: { email } });

    if (!user) {
      throw new UnauthorizedException('사용자를 찾을 수 없습니다');
    }

    const isPasswordValid = await bcrypt.compare(password, user.password);

    if (!isPasswordValid) {
      throw new UnauthorizedException('비밀번호가 일치하지 않습니다');
    }

    const { password: _, ...result } = user;
    return result;
  }

  async login(user: any) {
    const payload = {
      email: user.email,
      sub: user.id,
      roles: user.roles
    };

    return {
      access_token: this.jwtService.sign(payload),
      user: {
        id: user.id,
        email: user.email,
        name: user.name,
      },
    };
  }

  async register(email: string, password: string, name: string) {
    const existingUser = await this.userRepository.findOne({ where: { email } });

    if (existingUser) {
      throw new ConflictException('이미 존재하는 이메일입니다');
    }

    const hashedPassword = await bcrypt.hash(password, 10);

    const user = this.userRepository.create({
      email,
      password: hashedPassword,
      name,
      roles: ['user'],
    });

    await this.userRepository.save(user);

    const { password: _, ...result } = user;
    return result;
  }
}

  async validate(email: string, password: string) {
    return this.authService.validateUser(email, password);
  }
}

export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredRoles = this.reflector.getAllAndOverride<string[]>('roles', [
      context.getHandler(),
      context.getClass(),
    ]);

    if (!requiredRoles) {
      return true;
    }

    const request = context.switchToHttp().getRequest();
    const user = request.user;

    return requiredRoles.some((role) => user.roles?.includes(role));
  }
}

// ========== 6. Decorators ==========
export const Roles = (...roles: string[]) => SetMetadata('roles', roles);

export const CurrentUser = createParamDecorator(
  (data: unknown, ctx: ExecutionContext) => {
    const request = ctx.switchToHttp().getRequest();
    return request.user;
  },
);

// ========== 7. Auth Controller ==========
@Controller('auth')
export class AuthController {
  constructor(private authService: AuthService) {}

  @Post('register')
  async register(@Body() registerDto: { email: string; password: string; name: string }) {
    return this.authService.register(
      registerDto.email,
      registerDto.password,
      registerDto.name,
    );
  }

  @UseGuards(LocalAuthGuard)
  @Post('login')
  async login(@Request() req) {
    return this.authService.login(req.user);
  }
}

// ========== 8. User Controller ==========
@Controller('users')
export class UserController {
  @Get('profile')
  @UseGuards(JwtAuthGuard)
  getProfile(@CurrentUser() user: any) {
    return user;
  }

  @Delete(':id')
  @UseGuards(JwtAuthGuard, RolesGuard)
  @Roles('admin')
  deleteUser(@Param('id') id: number) {
    return { message: '사용자가 삭제되었습니다' };
  }
}

// ========== 9. Auth Module ==========
@Module({
  imports: [
    TypeOrmModule.forFeature([User]),
    PassportModule,
    JwtModule.register({
      secret: process.env.JWT_SECRET || 'your-secret-key',
      signOptions: { expiresIn: '1h' },
    }),
  ],
  providers: [
    AuthService,
    LocalStrategy,
    JwtStrategy,
    RolesGuard,
  ],
  controllers: [AuthController],
  exports: [AuthService],
})
export class AuthModule {}
```

**결과**:
- **안전한 인증**: bcrypt로 비밀번호 암호화
- **Stateless 인증**: JWT 토큰으로 서버 부담 감소
- **역할 기반 인가**: @Roles 데코레이터로 권한 관리
- **확장 가능**: OAuth, Refresh Token 등 쉽게 추가 가능
- **타입 안전**: TypeScript로 사용자 정보 타입 보장

## 💡 인사이트 & 깨달음

- **Passport는 Strategy 패턴의 완벽한 예시**: 인증 방식을 Strategy로 분리하여 확장 가능하게 설계
- **Guard는 선언적 보안**: `@UseGuards()`로 컨트롤러에 보안 로직을 선언하면, 비즈니스 로직과 완전히 분리됨
- **JWT의 양면성**: Stateless로 확장성은 좋지만, 토큰 탈취 시 만료 전까지 막을 방법이 없음. Refresh Token 필요
- **bcrypt의 중요성**: 절대 평문으로 비밀번호 저장 금지. bcrypt는 Salt를 자동으로 생성하고 느린 해싱으로 brute force 공격 방어
- **인증과 인가의 명확한 분리**: JwtAuthGuard는 인증, RolesGuard는 인가. 두 Guard를 조합하면 "로그인했고 + 관리자인" 조건 표현
- **ExecutionContext의 강력함**: HTTP뿐 아니라 WebSocket, gRPC 등 다양한 프로토콜에서 동일한 Guard 재사용 가능
- **Passport Strategy의 validate()**: 이 메서드의 리턴값이 req.user가 된다는 걸 이해하면 모든 게 명확해짐
- **@CurrentUser 데코레이터**: req.user를 매번 쓰는 것보다 커스텀 데코레이터가 코드 의도를 더 명확히 표현
