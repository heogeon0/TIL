## 📝 배운 내용

### NestJS Pipe, DTO 유틸리티, QueryBuilder 활용

오늘은 NestJS의 **Pipe**(ParseIntPipe, ParseArrayPipe), **DTO 유틸리티**(PickType 등), 그리고 **TypeORM QueryBuilder**의 장점과 사용법을 배웠다.

#### 1. ParseIntPipe - URL 파라미터 타입 변환

URL로 들어오는 파라미터는 기본적으로 **문자열(string)**이다. 이를 숫자로 변환하려면 `ParseIntPipe`를 사용한다.

**핵심 개념**:
- URL 파라미터는 항상 문자열로 전달됨
- `ParseIntPipe`는 문자열을 정수로 자동 변환
- 변환 실패 시 400 Bad Request 에러 자동 반환
- 타입 안정성 보장

**예제 코드**:
```typescript
import { Controller, Get, Param, ParseIntPipe } from '@nestjs/common';

@Controller('users')
export class UsersController {
  // ❌ 잘못된 방법: 문자열로 받아서 수동 변환
  @Get(':id')
  async getUserBad(@Param('id') id: string) {
    const userId = parseInt(id); // 매번 수동 변환 필요
    if (isNaN(userId)) {
      throw new BadRequestException('Invalid ID');
    }
    return this.usersService.findOne(userId);
  }

  // ✅ 올바른 방법: ParseIntPipe 사용
  @Get(':id')
  async getUserGood(@Param('id', ParseIntPipe) id: number) {
    // id는 이미 number 타입으로 변환됨
    return this.usersService.findOne(id);
  }
}
```

**결과**:
```bash
# 정상 요청
GET /users/123
→ id = 123 (number 타입)

# 잘못된 요청
GET /users/abc
→ 400 Bad Request: Validation failed (numeric string is expected)
```

**ParseIntPipe 옵션**:
```typescript
@Get(':id')
async getUser(
  @Param('id', new ParseIntPipe({
    errorHttpStatusCode: HttpStatus.NOT_ACCEPTABLE // 커스텀 에러 코드
  }))
  id: number
) {
  return this.usersService.findOne(id);
}
```

#### 2. ParseArrayPipe - 배열 파라미터 파싱

쿼리 스트링으로 배열을 받을 때 사용하는 Pipe다. 쉼표로 구분된 문자열을 배열로 변환하고, 각 요소의 타입도 검증한다.

**핵심 개념**:
- 쿼리 스트링의 쉼표 구분 값을 배열로 변환
- 배열 요소의 타입 검증 가능 (items 옵션)
- separator 옵션으로 구분자 커스터마이징
- 선택적(optional) 배열 처리 가능

**예제 코드**:
```typescript
import { Controller, Get, Query, ParseArrayPipe } from '@nestjs/common';

@Controller('posts')
export class PostsController {
  // 기본 사용: 문자열 배열
  @Get()
  async getPosts(
    @Query('tags', new ParseArrayPipe({ items: String, separator: ',' }))
    tags: string[],
  ) {
    // GET /posts?tags=nestjs,typescript,backend
    // tags = ['nestjs', 'typescript', 'backend']
    return this.postsService.findByTags(tags);
  }

  // 숫자 배열 파싱
  @Get('by-ids')
  async getPostsByIds(
    @Query('ids', new ParseArrayPipe({ items: Number, separator: ',' }))
    ids: number[],
  ) {
    // GET /posts/by-ids?ids=1,2,3,4,5
    // ids = [1, 2, 3, 4, 5] (number[] 타입)
    return this.postsService.findByIds(ids);
  }

  // 선택적(optional) 배열
  @Get('search')
  async searchPosts(
    @Query('categories', new ParseArrayPipe({
      items: String,
      separator: ',',
      optional: true // 파라미터가 없어도 에러 발생 안함
    }))
    categories?: string[],
  ) {
    // GET /posts/search (categories 없음)
    // categories = undefined

    // GET /posts/search?categories=tech,news
    // categories = ['tech', 'news']
    return this.postsService.search(categories);
  }
}
```

**결과**:
```bash
# 문자열 배열
GET /posts?tags=nodejs,express,fastify
→ tags = ['nodejs', 'express', 'fastify']

# 숫자 배열
GET /posts/by-ids?ids=10,20,30
→ ids = [10, 20, 30]

# 잘못된 요청 (숫자 배열에 문자 포함)
GET /posts/by-ids?ids=10,abc,30
→ 400 Bad Request: Validation failed
```

#### 3. PickType - DTO 유틸리티

기존 DTO 클래스에서 **일부 필드만 선택**해서 새로운 DTO를 만드는 유틸리티. 코드 중복을 줄이고 DRY 원칙을 지킬 수 있다.

**핵심 개념**:
- 기존 DTO에서 필요한 필드만 뽑아서 새 DTO 생성
- 타입 안정성 유지
- 다른 유틸리티: `OmitType`, `PartialType`, `IntersectionType`

**관련 유틸리티 비교**:

| 유틸리티 | 설명 | 사용 예시 |
|---------|------|-----------|
| **PickType** | 특정 필드만 **선택** | 로그인 시 email, password만 필요 |
| **OmitType** | 특정 필드만 **제외** | 업데이트 시 id 제외 |
| **PartialType** | 모든 필드를 **선택적**으로 | 부분 업데이트 |
| **IntersectionType** | 두 DTO를 **합침** | User + Profile 정보 합치기 |

**예제 코드**:
```typescript
import { PickType, OmitType, PartialType } from '@nestjs/mapped-types';
import { IsString, IsEmail, IsInt, MinLength } from 'class-validator';

// 기본 DTO (모든 필드 정의)
export class CreateUserDto {
  @IsString()
  @MinLength(2)
  name: string;

  @IsEmail()
  email: string;

  @IsString()
  @MinLength(8)
  password: string;

  @IsInt()
  age: number;

  @IsString()
  address: string;
}

// 1. PickType: 로그인에는 email, password만 필요
export class LoginDto extends PickType(CreateUserDto, ['email', 'password']) {
  // email과 password 필드만 가져옴
  // 검증 데코레이터도 그대로 유지됨
}

// 2. OmitType: 업데이트 시 password 제외
export class UpdateUserDto extends OmitType(CreateUserDto, ['password']) {
  // password를 제외한 모든 필드
}

// 3. PartialType: 모든 필드를 선택적으로 (부분 업데이트)
export class PatchUserDto extends PartialType(CreateUserDto) {
  // 모든 필드가 optional (name?, email?, password?, ...)
}

// 4. 조합 사용: PickType + PartialType
export class UpdateProfileDto extends PartialType(
  PickType(CreateUserDto, ['name', 'age', 'address'])
) {
  // name, age, address만 선택하고, 모두 optional로
}
```

**Controller에서 사용**:
```typescript
@Controller('auth')
export class AuthController {
  @Post('register')
  async register(@Body() createUserDto: CreateUserDto) {
    // name, email, password, age, address 모두 필수
    return this.authService.register(createUserDto);
  }

  @Post('login')
  async login(@Body() loginDto: LoginDto) {
    // email, password만 필요
    return this.authService.login(loginDto);
  }

  @Patch('profile')
  async updateProfile(@Body() updateProfileDto: UpdateProfileDto) {
    // name, age, address 중 일부만 보내도 OK
    return this.authService.updateProfile(updateProfileDto);
  }
}
```

**결과**:
```json
// LoginDto 사용 - email, password만 허용
POST /auth/login
{
  "email": "user@example.com",
  "password": "12345678"
}
✅ 성공

// name 필드 추가하면?
POST /auth/login
{
  "email": "user@example.com",
  "password": "12345678",
  "name": "John"  // ❌ 무시됨 (whitelist: true 설정 시)
}
```

#### 4. TypeORM QueryBuilder - 복잡한 쿼리의 해결사

TypeORM의 `find()` 메서드는 간단한 쿼리에는 편하지만, 복잡한 조건이나 JOIN이 많아지면 한계가 있다. **QueryBuilder**는 SQL을 직접 작성하는 것처럼 유연하면서도 타입 안정성을 제공한다.

**TypeORM의 장점**:
1. **타입 안정성**: 컴파일 타임에 오류 발견
2. **자동 마이그레이션**: 스키마 변경 자동 추적
3. **관계 처리**: JOIN이 간단함 (`@ManyToOne`, `@OneToMany` 등)
4. **데이터베이스 독립성**: MySQL, PostgreSQL, SQLite 등 쉽게 전환
5. **QueryBuilder**: 복잡한 동적 쿼리 작성 가능

**핵심 개념**:
- `createQueryBuilder()`로 쿼리 빌더 생성
- 메서드 체이닝으로 쿼리 구성
- `where`, `andWhere`, `orWhere`로 조건 추가
- `leftJoin`, `innerJoin`으로 관계 조인
- 동적 쿼리 작성에 최적화

**예제 코드**:

**4-1. 기본 QueryBuilder 사용**
```typescript
import { Injectable } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import { Repository } from 'typeorm';
import { User } from './entities/user.entity';

@Injectable()
export class UsersService {
  constructor(
    @InjectRepository(User)
    private usersRepository: Repository<User>,
  ) {}

  // 기본 find() - 간단한 쿼리
  async findByEmail(email: string) {
    return this.usersRepository.findOne({ where: { email } });
  }

  // QueryBuilder - 별칭(alias) 사용
  async findActiveUsers() {
    return this.usersRepository
      .createQueryBuilder('user') // 'user'는 별칭(alias)
      .where('user.isActive = :isActive', { isActive: true })
      .getMany();
  }

  // 복잡한 조건: AND, OR 조합
  async findUsersByCondition(minAge: number, city?: string) {
    const query = this.usersRepository
      .createQueryBuilder('user')
      .where('user.age >= :minAge', { minAge });

    if (city) {
      query.andWhere('user.city = :city', { city });
    }

    return query.getMany();
  }
}
```

**4-2. JOIN 활용 (관계 로딩)**
```typescript
// Entity 정의
@Entity()
export class User {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  name: string;

  @OneToMany(() => Post, (post) => post.user)
  posts: Post[];
}

@Entity()
export class Post {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  title: string;

  @ManyToOne(() => User, (user) => user.posts)
  user: User;

  @OneToMany(() => Comment, (comment) => comment.post)
  comments: Comment[];
}

// Service에서 JOIN 사용
@Injectable()
export class PostsService {
  constructor(
    @InjectRepository(Post)
    private postsRepository: Repository<Post>,
  ) {}

  // LEFT JOIN으로 User 정보 함께 가져오기
  async findPostsWithUser() {
    return this.postsRepository
      .createQueryBuilder('post')
      .leftJoinAndSelect('post.user', 'user') // user 정보 포함
      .getMany();
  }

  // 여러 관계 JOIN
  async findPostsWithUserAndComments() {
    return this.postsRepository
      .createQueryBuilder('post')
      .leftJoinAndSelect('post.user', 'user')
      .leftJoinAndSelect('post.comments', 'comment')
      .where('post.isPublished = :isPublished', { isPublished: true })
      .orderBy('post.createdAt', 'DESC')
      .getMany();
  }

  // 특정 조건으로 JOIN
  async findPostsByUserAge(minAge: number) {
    return this.postsRepository
      .createQueryBuilder('post')
      .innerJoin('post.user', 'user') // INNER JOIN
      .where('user.age >= :minAge', { minAge })
      .andWhere('post.isPublished = :isPublished', { isPublished: true })
      .getMany();
  }
}
```

**4-3. 동적 쿼리 (검색 기능)**
```typescript
interface SearchPostsDto {
  title?: string;
  authorName?: string;
  minViews?: number;
  tags?: string[];
}

@Injectable()
export class PostsService {
  async searchPosts(searchDto: SearchPostsDto) {
    const query = this.postsRepository.createQueryBuilder('post');

    // 제목 검색 (부분 일치)
    if (searchDto.title) {
      query.andWhere('post.title LIKE :title', {
        title: `%${searchDto.title}%`
      });
    }

    // 작성자 이름 검색
    if (searchDto.authorName) {
      query
        .innerJoin('post.user', 'user')
        .andWhere('user.name LIKE :name', {
          name: `%${searchDto.authorName}%`
        });
    }

    // 최소 조회수
    if (searchDto.minViews) {
      query.andWhere('post.views >= :minViews', {
        minViews: searchDto.minViews
      });
    }

    // 태그 검색 (배열)
    if (searchDto.tags && searchDto.tags.length > 0) {
      query.andWhere('post.tags && ARRAY[:...tags]', {
        tags: searchDto.tags
      });
    }

    return query
      .orderBy('post.createdAt', 'DESC')
      .limit(20)
      .getMany();
  }
}
```

**4-4. 집계 함수 (COUNT, SUM, AVG)**
```typescript
@Injectable()
export class AnalyticsService {
  constructor(
    @InjectRepository(Post)
    private postsRepository: Repository<Post>,
  ) {}

  // 게시글 개수 세기
  async countPostsByUser(userId: number) {
    return this.postsRepository
      .createQueryBuilder('post')
      .where('post.userId = :userId', { userId })
      .getCount();
  }

  // GROUP BY와 집계
  async getPostStatsByUser() {
    return this.postsRepository
      .createQueryBuilder('post')
      .select('post.userId', 'userId')
      .addSelect('COUNT(post.id)', 'postCount')
      .addSelect('AVG(post.views)', 'avgViews')
      .addSelect('SUM(post.likes)', 'totalLikes')
      .groupBy('post.userId')
      .getRawMany();
  }

  // 결과 예시:
  // [
  //   { userId: 1, postCount: 5, avgViews: 120, totalLikes: 450 },
  //   { userId: 2, postCount: 3, avgViews: 80, totalLikes: 200 }
  // ]
}
```

**4-5. 페이지네이션 (Pagination)**
```typescript
interface PaginationDto {
  page: number;
  limit: number;
}

@Injectable()
export class PostsService {
  async getPaginatedPosts(paginationDto: PaginationDto) {
    const { page, limit } = paginationDto;
    const skip = (page - 1) * limit;

    const [posts, total] = await this.postsRepository
      .createQueryBuilder('post')
      .leftJoinAndSelect('post.user', 'user')
      .orderBy('post.createdAt', 'DESC')
      .skip(skip)
      .take(limit)
      .getManyAndCount(); // 데이터 + 총 개수

    return {
      data: posts,
      meta: {
        page,
        limit,
        total,
        totalPages: Math.ceil(total / limit),
      },
    };
  }
}
```

**결과**:
```json
// GET /posts?page=2&limit=10
{
  "data": [ /* 10개의 게시글 */ ],
  "meta": {
    "page": 2,
    "limit": 10,
    "total": 47,
    "totalPages": 5
  }
}
```

**4-6. QueryBuilder vs find() 비교**

| 특징 | find() | QueryBuilder |
|------|--------|--------------|
| **간단한 쿼리** | ✅ 매우 편함 | 코드가 길어짐 |
| **복잡한 조건** | ❌ 제한적 | ✅ 유연함 |
| **동적 쿼리** | ❌ 어려움 | ✅ 쉬움 |
| **JOIN** | `relations` 옵션 | ✅ 세밀한 제어 |
| **집계 함수** | ❌ 불가능 | ✅ 가능 |
| **Raw SQL** | ❌ 불가능 | ✅ 가능 |

```typescript
// find() - 간단한 경우
const user = await this.usersRepository.findOne({
  where: { email: 'test@example.com' },
  relations: ['posts'],
});

// QueryBuilder - 복잡한 경우
const user = await this.usersRepository
  .createQueryBuilder('user')
  .leftJoinAndSelect('user.posts', 'post')
  .where('user.email = :email', { email: 'test@example.com' })
  .andWhere('post.isPublished = :isPublished', { isPublished: true })
  .orderBy('post.createdAt', 'DESC')
  .getOne();
```

## 💡 인사이트 & 깨달음

- **Pipe는 자동 검증 + 변환의 조합**: ParseIntPipe는 단순히 변환만 하는게 아니라, 변환 실패 시 에러도 자동으로 던져준다. 코드가 정말 깔끔해진다.
- **ParseArrayPipe로 쿼리스트링 배열 처리 간단**: `?ids=1,2,3`을 수동으로 파싱하던 시절은 끝났다. items 옵션으로 타입까지 검증해주니 완벽하다.
- **PickType으로 DRY 원칙 지키기**: 똑같은 필드를 여러 DTO에 복붙하지 말자. PickType, OmitType, PartialType을 활용하면 유지보수가 훨씬 쉬워진다.
- **DTO 유틸리티는 조합 가능**: `PartialType(PickType(...))` 처럼 여러 유틸리티를 조합해서 사용할 수 있다는 게 강력하다.
- **QueryBuilder는 동적 쿼리의 핵심**: 검색 기능처럼 조건이 선택적으로 추가되는 경우, if문으로 andWhere를 추가하는 방식이 정말 직관적이다.
- **find()로 시작, 복잡해지면 QueryBuilder로**: 간단할 땐 find()로 빠르게 작성하고, 요구사항이 복잡해지면 QueryBuilder로 리팩토링하는 게 좋은 전략이다.
- **TypeORM의 타입 안정성은 큰 장점**: Raw SQL을 쓸 때는 오타나 컬럼명 변경을 런타임에만 알 수 있지만, QueryBuilder는 컴파일 타임에 잡아준다.
- **leftJoinAndSelect vs leftJoin**: `leftJoin`은 조건에만 사용하고, `leftJoinAndSelect`는 데이터를 실제로 가져올 때 사용한다. 성능 차이가 있으니 주의!
- **getManyAndCount()는 페이지네이션 필수**: 데이터와 총 개수를 한 번에 가져올 수 있어서 페이지네이션 구현이 간단해진다.
