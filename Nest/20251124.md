- **NestJS Exception Handling (예외 처리)**

	**예외 처리란?**
	- 애플리케이션에서 발생하는 에러를 일관된 형식으로 처리
	- 클라이언트에게 명확한 에러 메시지 전달
	- 서버 내부 에러 정보를 숨기고 보안 유지

	**NestJS 기본 Exception**

	NestJS는 HTTP 상태 코드에 맞는 다양한 Exception을 제공합니다.

	```typescript
	import {
	  BadRequestException,      // 400
	  UnauthorizedException,    // 401
	  ForbiddenException,       // 403
	  NotFoundException,        // 404
	  ConflictException,        // 409
	  InternalServerErrorException, // 500
	} from '@nestjs/common';
	```

	**기본 Exception 사용하기**

	```typescript
	@Injectable()
	export class UserService {
	  async findOne(id: number) {
	    const user = await this.userRepository.findOne({ where: { id } });

	    if (!user) {
	      throw new NotFoundException(`User with ID ${id} not found`);
	    }

	    return user;
	  }

	  async create(createUserDto: CreateUserDto) {
	    const existingUser = await this.userRepository.findOne({
	      where: { email: createUserDto.email },
	    });

	    if (existingUser) {
	      throw new ConflictException('Email already exists');
	    }

	    return this.userRepository.save(createUserDto);
	  }
	}
	```

- **Exception Filter (예외 필터)**

	**Exception Filter란?**
	- 애플리케이션에서 발생하는 모든 예외를 가로채서 처리
	- 에러 응답 형식을 통일
	- 로깅, 모니터링 등 부가 기능 추가 가능

	**기본 Exception Filter 생성**

	```typescript
	// filters/http-exception.filter.ts
	import {
	  ExceptionFilter,
	  Catch,
	  ArgumentsHost,
	  HttpException,
	  HttpStatus,
	} from '@nestjs/common';
	import { Request, Response } from 'express';

	@Catch(HttpException)
	export class HttpExceptionFilter implements ExceptionFilter {
	  catch(exception: HttpException, host: ArgumentsHost) {
	    const ctx = host.switchToHttp();
	    const response = ctx.getResponse<Response>();
	    const request = ctx.getRequest<Request>();
	    const status = exception.getStatus();

	    response.status(status).json({
	      statusCode: status,
	      timestamp: new Date().toISOString(),
	      path: request.url,
	      method: request.method,
	      message: exception.message,
	    });
	  }
	}
	```

	**모든 예외 처리하기**

	```typescript
	@Catch() // 인자 없으면 모든 예외 처리
	export class AllExceptionsFilter implements ExceptionFilter {
	  catch(exception: unknown, host: ArgumentsHost) {
	    const ctx = host.switchToHttp();
	    const response = ctx.getResponse<Response>();
	    const request = ctx.getRequest<Request>();

	    const status =
	      exception instanceof HttpException
	        ? exception.getStatus()
	        : HttpStatus.INTERNAL_SERVER_ERROR;

	    const message =
	      exception instanceof HttpException
	        ? exception.message
	        : 'Internal server error';

	    // 에러 로깅
	    console.error('Error occurred:', {
	      timestamp: new Date().toISOString(),
	      path: request.url,
	      error: exception,
	    });

	    response.status(status).json({
	      statusCode: status,
	      timestamp: new Date().toISOString(),
	      path: request.url,
	      message,
	    });
	  }
	}
	```

	**고급 Exception Filter 예제**

	```typescript
	@Catch()
	export class GlobalExceptionFilter implements ExceptionFilter {
	  constructor(private readonly logger: Logger) {}

	  catch(exception: unknown, host: ArgumentsHost) {
	    const ctx = host.switchToHttp();
	    const response = ctx.getResponse<Response>();
	    const request = ctx.getRequest<Request>();

	    let status = HttpStatus.INTERNAL_SERVER_ERROR;
	    let message = 'Internal server error';
	    let errorCode = 'INTERNAL_ERROR';

	    if (exception instanceof HttpException) {
	      status = exception.getStatus();
	      const exceptionResponse = exception.getResponse();

	      if (typeof exceptionResponse === 'object') {
	        message = (exceptionResponse as any).message || exception.message;
	        errorCode = (exceptionResponse as any).error || 'HTTP_EXCEPTION';
	      } else {
	        message = exception.message;
	      }
	    } else if (exception instanceof Error) {
	      message = exception.message;
	    }

	    // 로깅
	    this.logger.error(
	      `${request.method} ${request.url}`,
	      exception instanceof Error ? exception.stack : 'Unknown error',
	      'ExceptionFilter',
	    );

	    // 에러 응답
	    response.status(status).json({
	      success: false,
	      statusCode: status,
	      errorCode,
	      message,
	      timestamp: new Date().toISOString(),
	      path: request.url,
	      method: request.method,
	    });
	  }
	}
	```

- **Class Validator (유효성 검증)**

	**Class Validator란?**
	- DTO의 데이터 유효성을 자동으로 검증
	- 데코레이터 기반으로 간편하게 검증 규칙 설정
	- 잘못된 데이터가 서비스 로직에 들어가는 것을 사전 차단

	**설치**
	```bash
	npm install class-validator class-transformer
	```

	**전역 ValidationPipe 설정**
	```typescript
	// main.ts
	import { ValidationPipe } from '@nestjs/common';

	async function bootstrap() {
	  const app = await NestFactory.create(AppModule);

	  app.useGlobalPipes(
	    new ValidationPipe({
	      whitelist: true,       // DTO에 없는 속성 제거
	      forbidNonWhitelisted: true, // DTO에 없는 속성 있으면 에러
	      transform: true,       // 타입 자동 변환 (string → number 등)
	    }),
	  );

	  await app.listen(3000);
	}
	bootstrap();
	```

	```typescript
	import {
	  IsString,
	  IsEmail,
	  IsInt,
	  IsNotEmpty,
	  MinLength,
	  MaxLength,
	  Min,
	  Max,
	  IsOptional,
	  IsEnum,
	  IsBoolean,
	  IsDate,
	  Matches,
	  IsArray,
	  ValidateNested,
	  ArrayMinSize,
	} from 'class-validator';
	import { Type } from 'class-transformer';

	export class CreateUserDto {
	  @IsEmail({}, { message: '올바른 이메일 형식이 아닙니다' })
	  @IsNotEmpty({ message: '이메일은 필수입니다' })
	  email: string;

	  @IsString({ message: '비밀번호는 문자열이어야 합니다' })
	  @MinLength(8, { message: '비밀번호는 최소 8자 이상이어야 합니다' })
	  @MaxLength(20, { message: '비밀번호는 최대 20자 이하여야 합니다' })
	  @Matches(/^(?=.*[A-Za-z])(?=.*\d)[A-Za-z\d@$!%*#?&]+$/, {
	    message: '비밀번호는 영문, 숫자를 포함해야 합니다',

	  password: string;

	  @IsString()
	  @MinLength(2)
	  @MaxLength(50)
	  name: string;

	  @IsInt({ message: '나이는 정수여야 합니다' })
	  @Min(1, { message: '나이는 1 이상이어야 합니다' })
	  @Max(120, { message: '나이는 120 이하여야 합니다' })

	  age?: number;

	  @IsEnum(['male', 'female', 'other'])
	  @IsOptional()

	}
	```

	**커스텀 Validator 생성**

	```typescript
	import {
	  ValidatorConstraint,
	  ValidatorConstraintInterface,
	  ValidationArguments,
	  ValidationOptions,
	  registerDecorator,
	} from 'class-validator';

	// 커스텀 Validator 로직
	@ValidatorConstraint({ name: 'isStrongPassword', async: false })
	export class IsStrongPasswordConstraint implements ValidatorConstraintInterface {
	  validate(password: string, args: ValidationArguments) {
	    // 최소 8자, 대소문자, 숫자, 특수문자 포함
	    const regex = /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[@$!%*?&])[A-Za-z\d@$!%*?&]{8,}$/;
	    return regex.test(password);
	  }

	  defaultMessage(args: ValidationArguments) {
	    return '비밀번호는 8자 이상, 대소문자, 숫자, 특수문자를 포함해야 합니다';
	  }
	}

	// 데코레이터 함수
	export function IsStrongPassword(validationOptions?: ValidationOptions) {
	  return function (object: Object, propertyName: string) {
	    registerDecorator({
	      target: object.constructor,
	      propertyName: propertyName,
	      options: validationOptions,
	      constraints: [],
	      validator: IsStrongPasswordConstraint,
	    });
	  };
	}

	// 사용
	export class CreateUserDto {
	  @IsStrongPassword()
	  password: string;
	}
	```

- **Request Lifecycle (요청 생명주기)**

	**Request Lifecycle이란?**
	- 클라이언트 요청이 들어와서 응답이 나갈 때까지의 전체 흐름
	- NestJS가 요청을 처리하는 순서를 이해하면 디버깅과 최적화에 유리

	**NestJS Request Lifecycle 순서**

	```
	1. Incoming Request (요청 도착)
	       ↓
	2. Middleware (미들웨어)
	       ↓
	3. Guard (가드)
	       ↓
	4. Interceptor (Before - 인터셉터 전처리)
	       ↓
	5. Pipe (파이프 - 데이터 변환/검증)
	       ↓
	6. Controller (컨트롤러)
	       ↓
	7. Service (서비스)
	       ↓
	8. Interceptor (After - 인터셉터 후처리)
	       ↓
	9. Exception Filter (에러 발생 시)
	       ↓
	10. Response (응답)
	```

	**각 단계 상세 설명**

	**1. Middleware (미들웨어)**
	- 요청이 라우터 핸들러에 도달하기 전 실행
	- 로깅, 인증 토큰 파싱, CORS 등

	```typescript
	@Injectable()
	export class LoggerMiddleware implements NestMiddleware {
	  use(req: Request, res: Response, next: NextFunction) {
	    console.log(`[Middleware] ${req.method} ${req.url}`);
	    next();
	  }
	}
	```

	**2. Guard (가드)**
	- 요청을 컨트롤러로 보낼지 말지 결정
	- 인증/인가 체크

	```typescript
	@Injectable()
	export class AuthGuard implements CanActivate {
	  canActivate(context: ExecutionContext): boolean {
	    const request = context.switchToHttp().getRequest();
	    console.log('[Guard] Checking authentication');
	    return !!request.headers.authorization; // 토큰 있으면 통과
	  }
	}
	```

	**3. Interceptor (Before)**
	- 컨트롤러 실행 전 로직
	- 요청 로깅, 데이터 변환 등

	```typescript
	@Injectable()
	export class LoggingInterceptor implements NestInterceptor {
	  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
	    console.log('[Interceptor Before] Request processing...');
	    const now = Date.now();

	    return next.handle().pipe(
	      tap(() => {
	        console.log(`[Interceptor After] Response time: ${Date.now() - now}ms`);
	      }),
	    );
	  }
	}
	```

	**4. Pipe (파이프)**
	- 데이터 변환 및 검증
	- ValidationPipe, ParseIntPipe 등

	```typescript
	@Get(':id')
	findOne(@Param('id', ParseIntPipe) id: number) {
	  // id가 숫자가 아니면 여기 도달하기 전에 에러
	  return this.userService.findOne(id);
	}
	```

	**5. Controller & Service**
	- 실제 비즈니스 로직 실행

	**6. Interceptor (After)**
	- 응답 데이터 변환

	**7. Exception Filter**
	- 에러가 발생하면 여기서 처리

	**실전 예제: 전체 Lifecycle 추적**

	```typescript
	// ========== 1. Middleware ==========
	@Injectable()
	export class LoggerMiddleware implements NestMiddleware {
	  use(req: Request, res: Response, next: NextFunction) {
	    console.log('1️⃣ [Middleware] Request received');
	    next();
	  }
	}

	// ========== 2. Guard ==========
	@Injectable()
	export class AuthGuard implements CanActivate {
	  canActivate(context: ExecutionContext): boolean {
	    console.log('2️⃣ [Guard] Checking authentication');
	    return true; // 통과
	  }
	}

	// ========== 3. Interceptor ==========
	@Injectable()
	export class LoggingInterceptor implements NestInterceptor {
	  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
	    console.log('3️⃣ [Interceptor Before] Before handler');

	    return next.handle().pipe(
	      tap(() => console.log('6️⃣ [Interceptor After] After handler')),
	    );
	  }
	}

	// ========== 4. Pipe ==========
	@Injectable()
	export class ValidationPipe implements PipeTransform {
	  transform(value: any, metadata: ArgumentMetadata) {
	    console.log('4️⃣ [Pipe] Validating and transforming');
	    return value;
	  }
	}

	// ========== 5. Controller ==========
	@Controller('users')
	@UseGuards(AuthGuard)
	@UseInterceptors(LoggingInterceptor)
	export class UserController {
	  constructor(private userService: UserService) {}

	  @Post()
	  create(@Body(ValidationPipe) createUserDto: CreateUserDto) {
	    console.log('5️⃣ [Controller] Executing handler');
	    return this.userService.create(createUserDto);
	  }
	}

	// ========== 6. Exception Filter ==========
	@Catch()
	export class AllExceptionsFilter implements ExceptionFilter {
	  catch(exception: unknown, host: ArgumentsHost) {
	    console.log('7️⃣ [Exception Filter] Handling error');
	    // 에러 처리
	  }
	}
	```

	**실행 결과 (정상 흐름)**
	```
	1️⃣ [Middleware] Request received
	2️⃣ [Guard] Checking authentication
	3️⃣ [Interceptor Before] Before handler
	4️⃣ [Pipe] Validating and transforming
	5️⃣ [Controller] Executing handler
	6️⃣ [Interceptor After] After handler
	```

	**실행 결과 (에러 발생 시)**
	```
	1️⃣ [Middleware] Request received
	2️⃣ [Guard] Checking authentication
	3️⃣ [Interceptor Before] Before handler
	4️⃣ [Pipe] Validating and transforming
	❌ [Validation Error]
	7️⃣ [Exception Filter] Handling error
	```

	**Lifecycle 단계별 적용 레벨**

	| 단계 | 전역 | 컨트롤러 | 메서드 |
	|------|------|----------|--------|
	| Middleware | ✅ | ✅ | ❌ |
	| Guard | ✅ | ✅ | ✅ |
	| Interceptor | ✅ | ✅ | ✅ |
	| Pipe | ✅ | ✅ | ✅ |
	| Exception Filter | ✅ | ✅ | ✅ |

**핵심 개념**:

**에러 처리 3단계 전략**
1. **예방 (Prevention)**: Class Validator로 잘못된 데이터 사전 차단
2. **대응 (Handling)**: Service에서 적절한 Exception 발생
3. **정리 (Formatting)**: Exception Filter로 일관된 응답 형식

**Exception vs Exception Filter**
- **Exception**: 에러를 "발생"시킴 (`throw new NotFoundException()`)
- **Exception Filter**: 발생한 에러를 "잡아서 처리"함 (`@Catch()`)

**ValidationPipe 주요 옵션**
```typescript
new ValidationPipe({
  whitelist: true,           // DTO에 없는 속성 자동 제거
  forbidNonWhitelisted: true, // DTO에 없는 속성 있으면 에러
  transform: true,            // 타입 자동 변환
  transformOptions: {
    enableImplicitConversion: true, // 암시적 타입 변환
  },
})
```

**Request Lifecycle 핵심 포인트**
- **순차 실행**: Middleware → Guard → Interceptor(Before) → Pipe → Controller → Interceptor(After)
- **에러 발생 시**: 어느 단계에서든 에러 발생 → 즉시 Exception Filter로 이동
- **Interceptor는 양방향**: Before와 After 모두 실행

**예제 코드**:
```typescript
// ============================================
// 완전한 예제: 사용자 등록 시스템
// ============================================

// ========== 1. DTO with Validation ==========
import { IsEmail, IsString, MinLength, IsOptional, IsInt, Min, Max } from 'class-validator';

export class CreateUserDto {
  @IsEmail({}, { message: '올바른 이메일 형식이 아닙니다' })
  email: string;

  @IsString()
  @MinLength(8, { message: '비밀번호는 최소 8자 이상이어야 합니다' })
  password: string;

  @IsString()
  @MinLength(2)
  name: string;

  @IsInt()
  @Min(1)
  @Max(120)
  @IsOptional()
  age?: number;
}

// ========== 2. Custom Exception ==========
export class UserAlreadyExistsException extends ConflictException {
  constructor(email: string) {
    super({
      statusCode: 409,
      message: `이미 존재하는 이메일입니다: ${email}`,
      errorCode: 'USER_ALREADY_EXISTS',
    });
  }
}

// ========== 3. Service with Exception ==========
@Injectable()
export class UserService {
  constructor(
    @InjectRepository(User)
    private userRepository: Repository<User>,
  ) {}

  async create(createUserDto: CreateUserDto) {
    // 중복 체크
    const existingUser = await this.userRepository.findOne({
      where: { email: createUserDto.email },
    });

    if (existingUser) {
      throw new UserAlreadyExistsException(createUserDto.email);
    }

    // 사용자 생성
    const user = this.userRepository.create(createUserDto);
    return this.userRepository.save(user);
  }

  async findOne(id: number) {
    const user = await this.userRepository.findOne({ where: { id } });

    if (!user) {
      throw new NotFoundException(`User with ID ${id} not found`);
    }

    return user;
  }
}

// ========== 4. Global Exception Filter ==========
@Catch()
export class GlobalExceptionFilter implements ExceptionFilter {
  constructor(private readonly logger: Logger) {}

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    let status = HttpStatus.INTERNAL_SERVER_ERROR;
    let message = 'Internal server error';
    let errorCode = 'INTERNAL_ERROR';

    if (exception instanceof HttpException) {
      status = exception.getStatus();
      const exceptionResponse = exception.getResponse();

      if (typeof exceptionResponse === 'object') {
        message = (exceptionResponse as any).message || exception.message;
        errorCode = (exceptionResponse as any).errorCode || 'HTTP_EXCEPTION';
      } else {
        message = exception.message;
      }
    }

    // 로깅
    this.logger.error(
      `${request.method} ${request.url} - ${status} ${errorCode}`,
      exception instanceof Error ? exception.stack : '',
    );

    // 응답
    response.status(status).json({
      success: false,
      statusCode: status,
      errorCode,
      message,
      timestamp: new Date().toISOString(),
      path: request.url,
    });
  }
}

// ========== 5. Controller with Lifecycle ==========
@Controller('users')
@UseGuards(AuthGuard)
@UseInterceptors(LoggingInterceptor)
export class UserController {
  constructor(private userService: UserService) {}

  @Post()
  @HttpCode(HttpStatus.CREATED)
  async create(@Body() createUserDto: CreateUserDto) {
    return this.userService.create(createUserDto);
  }

  @Get(':id')
  async findOne(@Param('id', ParseIntPipe) id: number) {
    return this.userService.findOne(id);
  }
}

// ========== 6. Main.ts 설정 ==========
async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // Global Validation Pipe
  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,
      forbidNonWhitelisted: true,
      transform: true,
    }),
  );

  // Global Exception Filter
  app.useGlobalFilters(new GlobalExceptionFilter(new Logger()));

  await app.listen(3000);
}
bootstrap();
```

## 💡 인사이트 & 깨달음

- **Exception은 비즈니스 로직의 일부**: 에러도 설계의 대상. "사용자가 없으면 404" 같은 명확한 규칙 필요
- **Validation은 가장 앞단에서**: 잘못된 데이터가 Service까지 가면 안 됨. Pipe에서 차단
- **Exception Filter는 최후의 보루**: 예상치 못한 에러도 여기서 잡아서 500 대신 의미 있는 응답 전달
- **Class Validator의 선언적 검증**: `if (password.length < 8)` 대신 `@MinLength(8)`. 코드가 문서가 됨
- **Request Lifecycle은 디버깅의 핵심**: "어디서 막혔나?"를 빠르게 파악 가능
- **Middleware vs Guard vs Interceptor**: 비슷해 보이지만 각자의 목적이 명확. Middleware는 Express 호환, Guard는 boolean 리턴, Interceptor는 Observable
- **Global 설정의 양면성**: 편하지만 특정 컨트롤러만 다르게 하고 싶을 때 복잡. 적절한 균형 필요
- **에러 메시지 국제화**: 한글로 하면 편하지만, i18n 고려하면 errorCode로 관리하는 게 나음
