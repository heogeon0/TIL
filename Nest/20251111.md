## 📝 배운 내용

#### 상세 내용
- **Express vs NestJS 차이점**
	**구조 및 아키텍처**
	- Express: 미니멀리스트 프레임워크로 구조를 개발자가 직접 설계
	- NestJS: 모듈 기반의 체계적인 아키텍처를 제공 (Angular와 유사)
	**타입 시스템**
	- Express: JavaScript 기반, TypeScript 사용 시 별도 설정 필요
	- NestJS: TypeScript 기본 지원, 타입 안정성 강화
	**의존성 주입 (DI)**
	- Express: DI 기능 없음, 직접 구현하거나 라이브러리 필요
	- NestJS: 내장 DI 컨테이너 제공으로 테스트와 유지보수 용이
	**코드 구조화**
	- Express: 미들웨어 중심의 선형적 구조
	- NestJS: 데코레이터 기반의 선언적 구조 (@Controller, @Injectable 등)
	**확장성**
	- Express: 유연하지만 대규모 프로젝트에서는 별도 설계 필요
	- NestJS: 대규모 애플리케이션을 위한 모듈화 및 확장성 고려한 설계
	**학습 곡선**
	- Express: 간단하고 배우기 쉬움
	- NestJS: 초기 학습 곡선이 있지만 장기적으로 유지보수 이점
	**기능**
	- Express: 기본적인 라우팅과 미들웨어 기능
	- NestJS: Guard, Interceptor, Pipe, Exception Filter 등 고급 기능 내장
- **Express의 미들웨어(Middleware)란?**
	- 요청(Request)과 응답(Response) 사이에서 실행되는 함수
	- 클라이언트 요청이 들어오면 최종 응답 전까지 중간에서 특정 작업 처리

	**미들웨어 구조**
	```javascript
	function middleware(req, res, next) {
	  // req: 요청 객체
	  // res: 응답 객체
	  // next: 다음 미들웨어 호출 함수
	  console.log('미들웨어 실행');
	  next(); // 다음으로 제어권 전달
	}
	```

	**미들웨어의 역할**
	- 요청 전처리 (데이터 검증, 파싱)
	- 인증/인가 (사용자 권한 확인)
	- 로깅 (요청/응답 기록)
	- 에러 처리
	- 응답 수정

	**미들웨어 실행 흐름**
	```javascript
	app.use((req, res, next) => {
	  console.log('1번 실행');
	  next(); // 다음으로 이동
	});

	app.use((req, res, next) => {
	  console.log('2번 실행');
	  next();
	});

	app.get('/user', (req, res) => {
	  console.log('3번 실행');
	  res.send('User Page');
	});
	// 실행 순서: 1번 → 2번 → 3번
	```

	**미들웨어 종류**
	- 애플리케이션 레벨: `app.use()` - 모든 요청에 실행
	- 라우터 레벨: `router.use()` - 특정 라우트에만 실행
	- 에러 처리: `(err, req, res, next) => {}` - 4개 파라미터
	- 내장 미들웨어: `express.json()`, `express.static()` 등
	- 서드파티: `cors`, `morgan` 등 외부 라이브러리

	**인증 미들웨어 예제**
	```javascript
	const authMiddleware = (req, res, next) => {
	  const token = req.headers.authorization;

	  if (!token) {
	    return res.status(401).json({ error: '인증 필요' });
	  }

	  req.user = { id: 1, name: 'John' };
	  next(); // 인증 성공 시 다음으로
	};

	// 보호된 라우트
	app.get('/private', authMiddleware, (req, res) => {
	  res.json({ user: req.user });
	});
	```

	**next()의 중요성**
	- `next()` 호출하지 않으면 요청이 멈춤
	- `next()`로 다음 미들웨어로 제어권 전달
	- `next('route')`: 다음 라우트로 스킵
	- `next(error)`: 에러 처리 미들웨어로 이동
