### QueryRunner를 활용한 트랜잭션 처리

TypeORM에서 트랜잭션을 처리하는 방법은 여러 가지가 있지만, **QueryRunner**를 사용하면 트랜잭션을 세밀하게 제어할 수 있다.

#### 1. 트랜잭션(Transaction)이란?

여러 개의 데이터베이스 작업을 **하나의 논리적 단위**로 묶어서 처리하는 것. 모든 작업이 성공하면 커밋(commit), 하나라도 실패하면 롤백(rollback)한다.

**ACID 원칙**:
- **Atomicity (원자성)**: 모두 성공 or 모두 실패
- **Consistency (일관성)**: 트랜잭션 전후로 데이터 일관성 유지
- **Isolation (격리성)**: 동시 실행되는 트랜잭션들이 서로 영향을 주지 않음
- **Durability (지속성)**: 커밋된 데이터는 영구적으로 저장

#### 2. TypeORM의 트랜잭션 처리 방법 비교

| 방법 | 사용 방식 | 장점 | 단점 |
|------|----------|------|------|
| **@Transaction 데코레이터** | `@Transaction()` | 간단하고 선언적 | 유연성 부족, deprecated |
| **Connection.transaction()** | `connection.transaction(async manager => {})` | 콜백 방식으로 깔끔 | 중첩 트랜잭션 복잡 |
| **QueryRunner** | `queryRunner.startTransaction()` | 세밀한 제어, 유연성 높음 | 코드가 길고 수동 관리 필요 |

#### 3. QueryRunner란?

**QueryRunner**는 데이터베이스 연결을 직접 제어할 수 있는 객체로, 트랜잭션을 시작하고 커밋하거나 롤백하는 모든 과정을 개발자가 직접 관리할 수 있다.

**주요 메서드**:
```typescript
queryRunner.connect()           // DB 연결
queryRunner.startTransaction()  // 트랜잭션 시작
queryRunner.commitTransaction() // 커밋
queryRunner.rollbackTransaction() // 롤백
queryRunner.release()           // 연결 해제 (필수!)
```

#### 4. 기본 QueryRunner 사용 예제

**핵심 개념**:
- QueryRunner를 생성하고 연결
- 트랜잭션 시작
- 작업 수행
- 성공 시 커밋, 실패 시 롤백
- **반드시** 연결 해제

**예제 코드**:
```typescript
import { Injectable } from '@nestjs/common';
import { DataSource } from 'typeorm';
import { User } from './entities/user.entity';
import { Account } from './entities/account.entity';

@Injectable()
export class UserService {
  constructor(private dataSource: DataSource) {}

  async createUserWithAccount(
    userName: string,
    email: string,
    initialBalance: number,
  ) {
    // 1. QueryRunner 생성
    const queryRunner = this.dataSource.createQueryRunner();

    // 2. 데이터베이스 연결
    await queryRunner.connect();

    // 3. 트랜잭션 시작
    await queryRunner.startTransaction();

    try {
      // 4. 첫 번째 작업: User 생성
      const user = queryRunner.manager.create(User, {
        name: userName,
        email: email,
      });
      await queryRunner.manager.save(user);

      // 5. 두 번째 작업: Account 생성
      const account = queryRunner.manager.create(Account, {
        userId: user.id,
        balance: initialBalance,
      });
      await queryRunner.manager.save(account);

      // 6. 모든 작업 성공 → 커밋
      await queryRunner.commitTransaction();

      return { user, account };
    } catch (error) {
      // 7. 오류 발생 → 롤백
      await queryRunner.rollbackTransaction();
      throw error;
    } finally {
      // 8. 연결 해제 (필수!)
      await queryRunner.release();
    }
  }
}
```

**결과**:
- User와 Account가 모두 생성되거나, 둘 다 생성되지 않음
- 중간에 오류 발생 시 모든 작업이 롤백됨

#### 5. 실전 예제: 계좌 이체 (송금)

계좌 이체는 트랜잭션이 필수적인 대표적인 예시다. A의 계좌에서 돈을 빼고, B의 계좌에 돈을 넣는 두 작업이 모두 성공하거나 모두 실패해야 한다.

```typescript
@Injectable()
export class AccountService {
  constructor(private dataSource: DataSource) {}

  async transfer(fromUserId: number, toUserId: number, amount: number) {
    const queryRunner = this.dataSource.createQueryRunner();
    await queryRunner.connect();
    await queryRunner.startTransaction();

    try {
      // 1. 송금자 계좌 조회
      const fromAccount = await queryRunner.manager.findOne(Account, {
        where: { userId: fromUserId },
      });

      if (!fromAccount) {
        throw new Error('송금자 계좌를 찾을 수 없습니다');
      }

      if (fromAccount.balance < amount) {
        throw new Error('잔액이 부족합니다');
      }

      // 2. 수신자 계좌 조회
      const toAccount = await queryRunner.manager.findOne(Account, {
        where: { userId: toUserId },
      });

      if (!toAccount) {
        throw new Error('수신자 계좌를 찾을 수 없습니다');
      }

      // 3. 송금자 계좌에서 차감
      fromAccount.balance -= amount;
      await queryRunner.manager.save(fromAccount);

      // 4. 수신자 계좌에 입금
      toAccount.balance += amount;
      await queryRunner.manager.save(toAccount);

      // 5. 거래 내역 저장
      const transaction = queryRunner.manager.create(Transaction, {
        fromUserId,
        toUserId,
        amount,
        timestamp: new Date(),
      });
      await queryRunner.manager.save(transaction);

      // 모든 작업 성공 → 커밋
      await queryRunner.commitTransaction();

      return {
        success: true,
        fromBalance: fromAccount.balance,
        toBalance: toAccount.balance,
      };
    } catch (error) {
      // 오류 발생 → 롤백
      await queryRunner.rollbackTransaction();
      throw error;
    } finally {
      // 연결 해제
      await queryRunner.release();
    }
  }
}
```

#### 6. QueryRunner의 고급 기능

**6-1. Raw Query 실행**

QueryRunner를 사용하면 순수 SQL 쿼리도 트랜잭션 내에서 실행할 수 있다.

```typescript
async updateWithRawQuery() {
  const queryRunner = this.dataSource.createQueryRunner();
  await queryRunner.connect();
  await queryRunner.startTransaction();

  try {
    // Raw SQL 실행
    await queryRunner.query(
      `UPDATE users SET status = ? WHERE created_at < ?`,
      ['inactive', new Date('2023-01-01')],
    );

    await queryRunner.query(
      `DELETE FROM sessions WHERE expired_at < ?`,
      [new Date()],
    );

    await queryRunner.commitTransaction();
  } catch (error) {
    await queryRunner.rollbackTransaction();
    throw error;
  } finally {
    await queryRunner.release();
  }
}
```

**6-2. 트랜잭션 격리 수준 설정**

동시성 제어를 위해 트랜잭션 격리 수준을 설정할 수 있다.

```typescript
await queryRunner.startTransaction('SERIALIZABLE');
// 또는
await queryRunner.startTransaction('READ COMMITTED');
```

격리 수준 종류:
- `READ UNCOMMITTED`: 가장 낮은 격리, Dirty Read 발생 가능
- `READ COMMITTED`: 커밋된 데이터만 읽음 (PostgreSQL 기본값)
- `REPEATABLE READ`: 트랜잭션 내에서 같은 결과 보장 (MySQL 기본값)
- `SERIALIZABLE`: 가장 높은 격리, 완전한 직렬화

#### 7. QueryRunner 사용 시 주의사항

1. **반드시 release() 호출**: finally 블록에서 항상 연결 해제
2. **에러 처리**: try-catch로 모든 에러를 잡아서 롤백 처리
3. **중첩 트랜잭션**: QueryRunner는 중첩 트랜잭션을 지원하지 않음
4. **긴 트랜잭션 피하기**: 트랜잭션이 길어지면 락(lock) 경합 발생
5. **manager 사용**: `queryRunner.manager`를 통해 엔티티 조작

**잘못된 예시 (연결 해제 누락)**:
```typescript
async badExample() {
  const queryRunner = this.dataSource.createQueryRunner();
  await queryRunner.connect();
  await queryRunner.startTransaction();

  await queryRunner.manager.save(user);
  await queryRunner.commitTransaction();

  // ❌ release() 누락 → 메모리 누수!
}
```

**올바른 예시**:
```typescript
async goodExample() {
  const queryRunner = this.dataSource.createQueryRunner();
  await queryRunner.connect();
  await queryRunner.startTransaction();

  try {
    await queryRunner.manager.save(user);
    await queryRunner.commitTransaction();
  } catch (error) {
    await queryRunner.rollbackTransaction();
    throw error;
  } finally {
    await queryRunner.release(); // ✅ 항상 실행됨
  }
}
```

#### 8. QueryRunner vs @Transactional 데코레이터

```typescript
// QueryRunner 방식 - 세밀한 제어
async transferWithQueryRunner(from: number, to: number, amount: number) {
  const queryRunner = this.dataSource.createQueryRunner();
  await queryRunner.connect();
  await queryRunner.startTransaction();

  try {
    // 복잡한 비즈니스 로직
    // 중간에 조건부로 롤백 가능
    if (someCondition) {
      await queryRunner.rollbackTransaction();
      return;
    }
    await queryRunner.commitTransaction();
  } catch (error) {
    await queryRunner.rollbackTransaction();
    throw error;
  } finally {
    await queryRunner.release();
  }
}

// @Transactional 방식 - 간단하지만 deprecated
@Transactional()
async transferWithDecorator(from: number, to: number, amount: number) {
  // 자동으로 트랜잭션 관리
  // 오류 발생 시 자동 롤백
}
```

#### 9. 실무 팁: Service에서 QueryRunner 재사용

여러 메서드에서 트랜잭션 로직을 재사용하려면 헬퍼 메서드를 만들 수 있다.

```typescript
@Injectable()
export class BaseService {
  constructor(protected dataSource: DataSource) {}

  protected async executeInTransaction<T>(
    work: (manager: EntityManager) => Promise<T>,
  ): Promise<T> {
    const queryRunner = this.dataSource.createQueryRunner();
    await queryRunner.connect();
    await queryRunner.startTransaction();

    try {
      const result = await work(queryRunner.manager);
      await queryRunner.commitTransaction();
      return result;
    } catch (error) {
      await queryRunner.rollbackTransaction();
      throw error;
    } finally {
      await queryRunner.release();
    }
  }
}

@Injectable()
export class UserService extends BaseService {
  async createUserWithAccount(name: string, email: string) {
    return this.executeInTransaction(async (manager) => {
      const user = manager.create(User, { name, email });
      await manager.save(user);

      const account = manager.create(Account, { userId: user.id });
      await manager.save(account);

      return { user, account };
    });
  }
}
```

## 💡 인사이트 & 깨달음

- **트랜잭션은 "모 아니면 도"의 세계**: 계좌 이체처럼 일관성이 중요한 작업에서는 트랜잭션이 필수다.
- **QueryRunner는 finally와 함께**: release()를 빼먹으면 메모리 누수가 발생한다. 반드시 finally 블록에서 해제해야 한다.
- **@Transaction 데코레이터는 deprecated**: TypeORM 0.3부터는 QueryRunner 사용이 권장된다.
- **간단한 작업엔 connection.transaction()**: 콜백 방식이 더 깔끔할 수 있다. 복잡한 제어가 필요할 때만 QueryRunner를 쓰자.
- **격리 수준은 성능과 트레이드오프**: SERIALIZABLE은 안전하지만 느리고, READ UNCOMMITTED는 빠르지만 데이터 일관성 문제가 있다.
- **긴 트랜잭션은 락 경합의 원인**: 트랜잭션 안에서는 필요한 작업만 하고, 외부 API 호출 같은 긴 작업은 트랜잭션 밖에서 처리하자.
- **Raw Query도 트랜잭션 가능**: queryRunner.query()로 순수 SQL도 트랜잭션 내에서 실행할 수 있다.
- **재사용 가능한 헬퍼 만들기**: executeInTransaction 같은 헬퍼 메서드를 만들면 보일러플레이트 코드를 줄일 수 있다.
