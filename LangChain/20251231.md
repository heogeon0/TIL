# TIL - 2025-12-31

## Runtime & State

LangChain의 Runtime은 에이전트 실행 환경을 관리하는 핵심 시스템입니다. **전역 상태 대신 요청별로 격리된 컨텍스트**를 제공하여 멀티테넌트 환경에 적합합니다.

### Runtime의 3가지 핵심 요소

1. **Context**: 사용자 ID, DB 연결 같은 정적 정보
2. **Store**: 장기 메모리용 저장소 인스턴스
3. **Stream writer**: 커스텀 스트림 모드를 통한 정보 전송

### Context Schema 정의

```javascript
import { createAgent } from "langchain";
import { z } from "zod";

const contextSchema = z.object({
  userName: z.string(),
  userId: z.string()
});

const agent = createAgent({
  model: "gpt-4o",
  tools: [],
  contextSchema
});

// 실행 시 컨텍스트 전달
const result = await agent.invoke(
  { messages: [{ role: "user", content: "내 이름이 뭐야?" }] },
  { context: { userName: "홍길동", userId: "user_123" } }
);
```

### 도구에서 Runtime 접근

```javascript
import { tool } from "langchain";
import { z } from "zod";

const fetchUserPreferences = tool(
  async (_, runtime) => {
    // Context에서 사용자 정보 추출
    const userName = runtime.context?.userName;

    // Store에서 장기 메모리 읽기
    if (runtime.store) {
      const memory = await runtime.store.get(["users"], userName);
      if (memory) {
        return memory.value.preferences;
      }
    }

    return "기본 설정";
  },
  {
    name: "fetch_user_preferences",
    description: "사용자 선호도를 조회합니다",
    schema: z.object({})
  }
);
```

### 미들웨어에서 Runtime 활용

```javascript
import { createMiddleware, SystemMessage } from "langchain";

const dynamicPromptMiddleware = createMiddleware({
  name: "DynamicPrompt",
  contextSchema,
  beforeModel: (state, runtime) => {
    const userName = runtime.context?.userName;

    const systemMsg = `당신은 도움이 되는 어시스턴트입니다.
      사용자 이름은 ${userName}입니다.`;

    return {
      messages: [new SystemMessage(systemMsg), ...state.messages]
    };
  }
});

const loggingMiddleware = createMiddleware({
  name: "Logging",
  contextSchema,
  beforeModel: (state, runtime) => {
    console.log(`요청 처리 중: ${runtime.context?.userName}`);
  },
  afterModel: (state, runtime) => {
    console.log(`요청 완료: ${runtime.context?.userName}`);
  }
});

const agent = createAgent({
  model: "gpt-4o",
  tools: [fetchUserPreferences],
  middleware: [dynamicPromptMiddleware, loggingMiddleware],
  contextSchema
});
```

### Runtime의 핵심 이점

| 특성 | 설명 |
|------|------|
| **상태 격리** | 전역 상태 없이 요청별로 독립적인 컨텍스트 |
| **재사용성** | 동일한 도구/미들웨어를 다양한 컨텍스트에서 활용 |
| **테스트 용이성** | 명시적 컨텍스트로 테스트 케이스 구성 간편 |
| **멀티테넌트** | 사용자별/조직별 데이터를 안전하게 분리 |

## 가드레일 (Guardrails)

에이전트의 **안전성 검사 및 콘텐츠 필터링**을 구현하는 시스템입니다. 민감한 정보 유출 방지, 부적절한 콘텐츠 차단, 비즈니스 규칙 강제 등에 활용됩니다.

### 결정론적 가드레일 (Deterministic Guardrails)

정규표현식, 키워드 매칭 등 **규칙 기반 로직**을 사용합니다.

- **장점**: 빠르고 예측 가능
- **단점**: 미묘한 위반은 놓칠 수 있음

```javascript
import { createAgent, piiRedactionMiddleware } from "langchain";

// PII(개인식별정보) 자동 감지 및 처리
const agent = createAgent({
  model: "gpt-4o",
  tools: [],
  middleware: [
    piiRedactionMiddleware({
      piiType: "email",
      strategy: "redact",        // [REDACTED_EMAIL]로 치환
      applyToInput: true         // 사용자 입력에 적용
    })
  ]
});
```

**지원하는 전략:**
- `redact`: `[REDACTED_EMAIL]`로 치환
- `mask`: `****-****-****-1234` 형태로 부분 마스킹
- `hash`: 결정론적 해시로 치환
- `block`: 감지 시 예외 발생

**내장 PII 타입:** email, credit_card, ip, mac_address, url

### 모델 기반 가드레일 (Model-based Guardrails)

LLM이나 분류기를 활용하여 **의미론적 이해**로 콘텐츠를 평가합니다.

- **장점**: 더 정교한 검증 가능
- **단점**: 비용과 속도 측면의 트레이드오프

```javascript
import { createMiddleware, AIMessage } from "langchain";
import { initChatModel } from "langchain";

const safetyGuardrailMiddleware = () => {
  const safetyModel = initChatModel("gpt-4o-mini");

  return createMiddleware({
    name: "SafetyGuardrail",
    afterAgent: {
      hook: async (state) => {
        const lastMessage = state.messages[state.messages.length - 1];

        const safetyPrompt = `응답이 안전하고 적절한지 평가하세요.
          'SAFE' 또는 'UNSAFE'만 응답하세요.

          응답: ${lastMessage.content.toString()}`;

        const result = await safetyModel.invoke([
          { role: "user", content: safetyPrompt }
        ]);

        if (result.content.toString().includes("UNSAFE")) {
          return {
            messages: [new AIMessage("해당 응답은 제공할 수 없습니다.")],
            jumpTo: "end"
          };
        }
      },
      canJumpTo: ["end"]
    }
  });
};
```

### 커스텀 가드레일

#### Before Agent Guardrails (사전 검증)

요청 시작 **전** 세션 수준의 검증을 수행합니다.

```javascript
import { createMiddleware, AIMessage } from "langchain";

const contentFilterMiddleware = (bannedKeywords) => {
  return createMiddleware({
    name: "ContentFilter",
    beforeAgent: {
      hook: (state) => {
        if (!state.messages?.length) return;

        const firstMessage = state.messages[0];
        const content = firstMessage.content.toString().toLowerCase();

        for (const keyword of bannedKeywords) {
          if (content.includes(keyword)) {
            return {
              messages: [
                new AIMessage("부적절한 콘텐츠는 처리할 수 없습니다.")
              ],
              jumpTo: "end"
            };
          }
        }
      },
      canJumpTo: ["end"]
    }
  });
};

// 사용
const agent = createAgent({
  model: "gpt-4o",
  middleware: [
    contentFilterMiddleware(["hack", "exploit", "crack"])
  ]
});
```

#### After Agent Guardrails (사후 검증)

최종 출력을 반환 **전**에 검증합니다. 주로 모델 기반 검증에 사용됩니다.

```javascript
const outputValidationMiddleware = createMiddleware({
  name: "OutputValidation",
  afterAgent: {
    hook: (state) => {
      const lastMessage = state.messages[state.messages.length - 1];
      const content = lastMessage.content.toString();

      // 비즈니스 규칙: 답변이 너무 짧은 경우
      if (content.length < 10) {
        return {
          messages: [
            new AIMessage("더 상세한 답변을 제공하겠습니다...")
          ],
          jumpTo: "end"
        };
      }
    },
    canJumpTo: ["end"]
  }
});
```

#### Combine Multiple Guardrails (다층 가드레일)

여러 가드레일을 미들웨어 배열에 순차적으로 추가합니다:

```javascript
import { humanInTheLoopMiddleware } from "langchain";

const agent = createAgent({
  model: "gpt-4o",
  tools: [sendEmailTool, deleteDatabaseTool],
  middleware: [
    // 1. 입력 필터링 (Before)
    contentFilterMiddleware(["spam", "malware"]),

    // 2. PII 삭제 (Deterministic)
    piiRedactionMiddleware({
      piiType: "email",
      strategy: "redact"
    }),

    // 3. 사람 승인 (Human-in-the-loop)
    humanInTheLoopMiddleware({
      interruptOn: {
        send_email: { allowAccept: true, allowEdit: true },
        delete_database: { allowAccept: true }
      }
    }),

    // 4. 출력 안전성 검증 (After, Model-based)
    safetyGuardrailMiddleware()
  ]
});
```

### Human-in-the-loop (사람 개입)

특정 도구 호출 시 사용자의 승인을 요구합니다:

```javascript
import { humanInTheLoopMiddleware } from "langchain";

const agent = createAgent({
  model: "gpt-4o",
  tools: [sendEmailTool, deleteDatabaseTool, searchTool],
  middleware: [
    humanInTheLoopMiddleware({
      interruptOn: {
        send_email: {
          allowAccept: true,   // 승인 허용
          allowEdit: true      // 수정 허용
        },
        delete_database: {
          allowAccept: true    // 승인만 가능
        },
        search: false          // 자동 승인
      }
    })
  ]
});
```

## Memory

에이전트가 **이전 상호작용을 기억**하고, 피드백에서 배우며, 사용자 선호도에 적응하는 핵심 시스템입니다.

### Short-term Memory (단기 메모리)

단일 세션 내에서 대화 컨텍스트를 유지합니다. **Thread** 단위로 관리됩니다.

#### Checkpointer 설정

```javascript
import { createAgent } from "langchain";
import { MemorySaver } from "@langchain/langgraph";

const checkpointer = new MemorySaver();

const agent = createAgent({
  model: "gpt-4o",
  tools: [],
  checkpointer
});

// 첫 번째 대화
await agent.invoke(
  { messages: [{ role: "user", content: "내 이름은 철수야" }] },
  { configurable: { thread_id: "session_1" } }
);

// 두 번째 대화 - 이전 대화를 기억
const result = await agent.invoke(
  { messages: [{ role: "user", content: "내 이름이 뭐였지?" }] },
  { configurable: { thread_id: "session_1" } }
);
// "철수라고 하셨습니다."
```

#### 프로덕션 환경 - PostgreSQL

```javascript
import { PostgresSaver } from "@langchain/langgraph-checkpoint-postgres";

const DB_URI = "postgresql://user:pass@localhost:5432/db";
const checkpointer = PostgresSaver.fromConnString(DB_URI);

const agent = createAgent({
  model: "gpt-4o",
  tools: [],
  checkpointer
});
```

#### 메시지 트리밍 (Context Window 관리)

긴 대화에서 컨텍스트 윈도우 초과를 방지합니다:

```javascript
import { RemoveMessage } from "@langchain/core/messages";
import { createMiddleware } from "langchain";
import { REMOVE_ALL_MESSAGES } from "@langchain/langgraph";

const trimMessagesMiddleware = createMiddleware({
  name: "TrimMessages",
  beforeModel: (state) => {
    const messages = state.messages;

    // 메시지가 3개 이하면 유지
    if (messages.length <= 3) return;

    // 첫 메시지(시스템 프롬프트)와 최근 3개만 유지
    const firstMsg = messages[0];
    const recentMessages = messages.slice(-3);

    return {
      messages: [
        new RemoveMessage({ id: REMOVE_ALL_MESSAGES }),
        firstMsg,
        ...recentMessages
      ]
    };
  }
});

const agent = createAgent({
  model: "gpt-4o",
  tools: [],
  middleware: [trimMessagesMiddleware],
  checkpointer
});
```

#### 메시지 요약 (정보 손실 방지)

오래된 메시지를 요약하여 컨텍스트를 압축합니다:

```javascript
import { summarizationMiddleware } from "langchain";

const agent = createAgent({
  model: "gpt-4o",
  tools: [],
  middleware: [
    summarizationMiddleware({
      model: "gpt-4o-mini",
      trigger: { tokens: 4000 },  // 4000 토큰 초과 시 요약
      keep: { messages: 20 }       // 최근 20개 메시지는 유지
    })
  ],
  checkpointer
});
```

#### 커스텀 상태 확장


### Long-term Memory (장기 메모리)

세션을 넘어서 지속적으로 정보를 저장합니다. **Store**를 통해 관리됩니다.

#### 메모리 저장소 구조

- **네임스페이스**: 사용자 ID, 조직 ID 등으로 구성된 폴더 역할
- **키**: 파일 이름처럼 개별 메모리를 식별
- **값**: JSON 문서로 저장

```javascript
import { InMemoryStore } from "@langchain/langgraph";

// 임베딩 함수 (실제로는 OpenAI Embeddings 사용)
const embed = (texts) => {
  return texts.map(() => [1.0, 2.0]);
};

const store = new InMemoryStore({
  index: { embed, dims: 2 }
});

const namespace = ["user-123", "preferences"];

// 메모리 저장
await store.put(namespace, "language", {
  preferred: "한국어",
  level: "advanced"
});

// 메모리 조회
const item = await store.get(namespace, "language");
console.log(item.value); // { preferred: "한국어", level: "advanced" }

// 메모리 검색
const items = await store.search(namespace, {
  filter: { level: "advanced" },
  query: "언어 선호도"
});
```

#### 도구에서 장기 메모리 읽기

```javascript
import { tool } from "langchain";
import { z } from "zod";

const getUserInfo = tool(
  async (_, runtime) => {
    const userId = runtime.context.userId;
    const userInfo = await runtime.store.get(["users"], userId);

    return userInfo?.value
      ? JSON.stringify(userInfo.value)
      : "사용자 정보 없음";
  },
  {
    name: "get_user_info",
    description: "사용자 정보 조회",
    schema: z.object({})
  }
);
```

#### 도구에서 장기 메모리 쓰기

```javascript
const saveUserPreferences = tool(
  async (preferences, runtime) => {
    const userId = runtime.context.userId;

    await runtime.store.put(
      ["users", "preferences"],
      userId,
      preferences
    );

    return "사용자 선호도가 저장되었습니다.";
  },
  {
    name: "save_user_preferences",
    description: "사용자 선호도 저장",
    schema: z.object({
      language: z.string(),
      theme: z.string()
    })
  }
);
```

#### 에이전트에 Store 통합

```javascript
import { createAgent } from "langchain";
import { InMemoryStore } from "@langchain/langgraph";

const store = new InMemoryStore({ index: { embed, dims: 2 } });
const checkpointer = new MemorySaver();

const contextSchema = z.object({
  userId: z.string()
});

const agent = createAgent({
  model: "gpt-4o",
  tools: [getUserInfo, saveUserPreferences],
  contextSchema,
  store,           // 장기 메모리
  checkpointer     // 단기 메모리
});

// 실행
await agent.invoke(
  {
    messages: [{
      role: "user",
      content: "내 언어 설정을 한국어로 저장해줘"
    }]
  },
  {
    context: { userId: "user_123" },
    configurable: { thread_id: "session_1" }
  }
);
```

### Short-term vs Long-term Memory 비교

| 구분 | Short-term Memory | Long-term Memory |
|------|------------------|------------------|
| **범위** | 단일 세션/대화 | 여러 세션 간 |
| **구현** | Checkpointer | Store |
| **저장소** | 메시지 히스토리 | Key-Value Store |
| **용도** | 대화 컨텍스트 유지 | 사용자 프로필, 선호도 |
| **예시** | "이전에 말했던 내용" | "사용자의 언어 설정" |

## Middleware Hooks 상세

미들웨어는 에이전트 실행 흐름의 특정 지점에서 실행되는 훅을 제공합니다. **Node-Style**과 **Wrap-Style** 두 가지 스타일이 있습니다.

### Node-Style Hooks (순차 실행)

특정 실행 지점에서 **순차적으로 실행**되며, 상태를 관찰하고 수정할 수 있습니다.

#### 사용 가능한 훅

- **`beforeAgent`**: 에이전트 시작 전 (호출당 1회)
- **`beforeModel`**: 각 모델 호출 전
- **`afterModel`**: 각 모델 응답 후
- **`afterAgent`**: 에이전트 완료 후 (호출당 1회)
- **`beforeTool`**: 각 도구 호출 전
- **`afterTool`**: 각 도구 실행 후

#### 특징

- 순차적으로 실행되며 자동으로 핸들러 호출
- 상태를 관찰하고 수정 가능
- **jumpTo**로 흐름 제어 가능

#### 예제: 메시지 제한 미들웨어

```javascript
import { createMiddleware, AIMessage } from "langchain";

const createMessageLimitMiddleware = (maxMessages = 50) => {
  return createMiddleware({
    name: "MessageLimitMiddleware",
    beforeModel: (state) => {
      // 메시지 개수 체크
      if (state.messages.length === maxMessages) {
        return {
          messages: [new AIMessage("대화 제한에 도달했습니다.")],
          jumpTo: "end"  // 에이전트 종료
        };
      }
      return; // 정상 진행
    },
    afterModel: (state) => {
      // 모델 응답 로깅
      const lastMessage = state.messages[state.messages.length - 1];
      console.log(`모델 응답: ${lastMessage.content}`);
      return;
    }
  });
};

const agent = createAgent({
  model: "gpt-4o",
  tools: [],
  middleware: [createMessageLimitMiddleware(50)]
});
```

#### 예제: 호출 횟수 추적

```javascript
const callCounterMiddleware = createMiddleware({
  name: "CallCounter",
  stateSchema: z.object({
    modelCallCount: z.number().default(0)
  }),
  beforeModel: (state) => {
    // 10회 초과 시 종료
    if (state.modelCallCount > 10) {
      return { jumpTo: "end" };
    }
    return;
  },
  afterModel: (state) => {
    // 호출 횟수 증가
    return { modelCallCount: state.modelCallCount + 1 };
  }
});
```

### Wrap-Style Hooks (제어 흐름)

실행을 **감싸고(wrap)** 핸들러 호출 여부를 직접 제어합니다.

#### 사용 가능한 훅

- **`wrapModelCall`**: 각 모델 호출 주변
- **`wrapToolCall`**: 각 도구 호출 주변

#### 특징

- 핸들러를 언제, 몇 번 호출할지 직접 제어
- 재시도, 캐싱, 요청 변환 구현 가능
- 핸들러 호출: 0번 (단락), 1번 (정상), N번 (재시도)

#### 예제: 재시도 미들웨어

```javascript
import { createMiddleware } from "langchain";

const createRetryMiddleware = (maxRetries = 3) => {
  return createMiddleware({
    name: "RetryMiddleware",
    wrapModelCall: (request, handler) => {
      for (let attempt = 0; attempt < maxRetries; attempt++) {
        try {
          // 핸들러 직접 호출
          return handler(request);
        } catch (e) {
          if (attempt === maxRetries - 1) {
            throw e;  // 마지막 시도에서 실패 시 에러
          }
          console.log(`재시도 ${attempt + 1}/${maxRetries}`);
        }
      }
      throw new Error("Unreachable");
    }
  });
};
```

#### 예제: 도구 호출 모니터링

```javascript
const toolMonitoringMiddleware = createMiddleware({
  name: "ToolMonitoring",
  wrapToolCall: (request, handler) => {
    console.log(`도구 실행: ${request.toolCall.name}`);
    console.log(`인자: ${JSON.stringify(request.toolCall.args)}`);

    const startTime = Date.now();
    try {
      const result = handler(request);
      const duration = Date.now() - startTime;
      console.log(`도구 성공 (${duration}ms)`);
      return result;
    } catch (e) {
      console.log(`도구 실패: ${e}`);
      throw e;
    }
  }
});
```

#### 예제: 동적 모델 선택

```javascript
import { initChatModel } from "langchain";

const dynamicModelMiddleware = createMiddleware({
  name: "DynamicModel",
  wrapModelCall: (request, handler) => {
    const modifiedRequest = { ...request };

    // 메시지가 많으면 강력한 모델, 적으면 경량 모델
    if (request.messages.length > 10) {
      modifiedRequest.model = initChatModel("gpt-4o");
    } else {
      modifiedRequest.model = initChatModel("gpt-4o-mini");
    }

    return handler(modifiedRequest);
  }
});
```

#### 예제: 캐싱 미들웨어

```javascript
const cache = new Map();

const cachingMiddleware = createMiddleware({
  name: "Caching",
  wrapModelCall: (request, handler) => {
    const cacheKey = JSON.stringify(request.messages);

    // 캐시 확인
    if (cache.has(cacheKey)) {
      console.log("캐시 히트!");
      return cache.get(cacheKey);
    }

    // 핸들러 호출 및 캐시 저장
    const result = handler(request);
    cache.set(cacheKey, result);
    return result;
  }
});
```

### Node-Style vs Wrap-Style 비교

| 구분 | Node-Style | Wrap-Style |
|------|-----------|-----------|
| **실행 패턴** | 순차적, 자동 호출 | 함수형 래핑, 수동 호출 |
| **제어 수준** | 상태 수정, jumpTo로 종료 | 핸들러 호출 제어 (0/1/N번) |
| **사용 사례** | 로깅, 검증, 상태 업데이트 | 재시도, 캐싱, 요청 변환 |
| **핸들러 호출** | 자동 (항상 실행) | 선택적 (직접 제어) |
| **반환값** | 상태 업데이트 객체 | 핸들러 결과 |

### 실행 순서

여러 미들웨어를 조합할 때 실행 순서:

```javascript
const agent = createAgent({
  model: "gpt-4o",
  tools: [],
  middleware: [middleware1, middleware2, middleware3]
});
```

**실행 흐름:**
1. `middleware1.beforeModel` → `middleware2.beforeModel` → `middleware3.beforeModel`
2. `middleware1.wrapModelCall` 시작 → `middleware2.wrapModelCall` 시작 → `middleware3.wrapModelCall` 시작
3. **실제 모델 호출**
4. `middleware3.wrapModelCall` 종료 → `middleware2.wrapModelCall` 종료 → `middleware1.wrapModelCall` 종료
5. `middleware3.afterModel` → `middleware2.afterModel` → `middleware1.afterModel` (역순)

### 모범 사례

1. **단일 책임 원칙**: 각 미들웨어는 하나의 기능만 담당
2. **Node-style 우선**: 단순 로깅/검증은 Node-style 사용
3. **Wrap-style 선택**: 재시도, 캐싱, 흐름 제어가 필요한 경우만 사용
4. **에러 처리**: 미들웨어 오류를 우아하게 처리
5. **독립성**: 미들웨어 간 의존성 최소화

### 실전 조합 예제

```javascript
const agent = createAgent({
  model: "gpt-4o",
  tools: [searchTool],
  middleware: [
    // 1. Node-style: 요청 로깅
    createMiddleware({
      name: "RequestLogger",
      beforeModel: (state) => {
        console.log(`요청 시작: ${state.messages.length}개 메시지`);
      }
    }),

    // 2. Wrap-style: 재시도
    createRetryMiddleware(3),

    // 3. Wrap-style: 캐싱
    cachingMiddleware,

    // 4. Node-style: 응답 검증
    createMiddleware({
      name: "ResponseValidator",
      afterModel: (state) => {
        const lastMsg = state.messages[state.messages.length - 1];
        if (!lastMsg.content) {
          console.warn("빈 응답 감지!");
        }
      }
    })
  ]
});
```

## 📝 배운 내용

### 핵심 개념

#### Runtime & State
- **Runtime**: 에이전트 실행 환경을 관리하는 시스템
- **Context**: 요청별로 격리된 정적 정보 (사용자 ID, DB 연결 등)
- **Store**: 장기 메모리 저장소
- **전역 상태 회피**: 멀티테넌트 환경에서 안전한 상태 관리

#### Guardrails (보안 계층)
- **결정론적 가드레일**: 규칙 기반 (정규식, 키워드), 빠르지만 제한적
- **모델 기반 가드레일**: LLM 활용, 정교하지만 비용/속도 트레이드오프
- **Before Agent**: 요청 전 검증 (입력 필터링)
- **After Agent**: 응답 후 검증 (출력 검증)
- **Human-in-the-loop**: 중요 작업 시 사람 승인 요구

#### Memory (기억 시스템)
- **Short-term Memory**:
  - Thread 단위로 세션 내 대화 컨텍스트 유지
  - Checkpointer로 구현
  - 메시지 트리밍, 요약으로 Context Window 관리

- **Long-term Memory**:
  - Store로 세션 간 정보 지속
  - 네임스페이스/키/값 구조
  - 사용자 프로필, 선호도 저장

#### Middleware Hooks (실행 제어)
- **Node-Style Hooks**:
  - 순차적 실행 (beforeAgent, beforeModel, afterModel, afterAgent 등)
  - 상태 관찰 및 수정
  - jumpTo로 흐름 제어
  - 용도: 로깅, 검증, 상태 업데이트

- **Wrap-Style Hooks**:
  - 함수형 래핑 (wrapModelCall, wrapToolCall)
  - 핸들러 호출 직접 제어 (0/1/N번)
  - 용도: 재시도, 캐싱, 요청 변환

- **실행 순서**: before (순방향) → wrap (중첩) → 모델 호출 → wrap 종료 → after (역순)

### 주요 패턴

1. **Runtime을 활용한 컨텍스트 전달**
   ```javascript
   // 도구에서 runtime.context, runtime.store 접근
   const tool = async (_, runtime) => {
     const userId = runtime.context.userId;
     const data = await runtime.store.get(["users"], userId);
   };
   ```

2. **다층 가드레일 구성**
   ```javascript
   middleware: [
     contentFilter,      // Before
     piiRedaction,       // Deterministic
     humanInTheLoop,     // Interactive
     safetyCheck         // After, Model-based
   ]
   ```

3. **단기/장기 메모리 조합**
   ```javascript
   const agent = createAgent({
     checkpointer,  // 대화 기억
     store          // 사용자 정보 저장
   });
   ```

## 💡 인사이트 & 깨달음

- **Runtime의 가치**: 전역 상태 대신 명시적 컨텍스트 전달로 **테스트 용이성**과 **멀티테넌트 안전성** 확보
- **가드레일 계층화**: 빠른 결정론적 검사 → 사람 개입 → 정교한 모델 검증 순서로 구성하면 **비용과 안전성 균형** 달성
- **메모리 분리 원칙**:
  - Short-term: "이번 대화에서 뭐라고 했더라?" (Checkpointer)
  - Long-term: "이 사용자는 항상 한국어를 선호해" (Store)
- **Context Window 관리의 중요성**: 긴 대화는 토큰 초과로 실패 → 트리밍/요약 필수
- **Human-in-the-loop**: 완전 자동화보다 중요한 작업에서 사람 승인을 받는 것이 **실용적이고 안전함**
- **미들웨어 선택 전략**:
  - Node-style: 간단한 로깅/검증에 적합, 코드가 직관적
  - Wrap-style: 재시도/캐싱처럼 핸들러 제어가 필요할 때만 사용
  - 두 스타일을 조합하면 강력한 에이전트 파이프라인 구축 가능
- **미들웨어 실행 순서**: wrap은 양파처럼 중첩(middleware1이 가장 바깥), after는 역순 실행 → 디버깅 시 유의
