 
 # TIL - 한입크기로 잘라먹는 Next.js

## 키워드
NEXT.JS, 리액트 서버컴포넌트

## 오늘 배운 내용
- ServerComponent
     - 서버에서만 실행되는 리액트 컴포넌트
          - PageRouter의 문제
               - 하이드레이션을 위해 모든 JS를 JS Bundle로 만들어주지만, 이 때 상호작용이 없는 하이드레이션이 필요없는 JS도 전달됨 -> 불필요한 번들 사이즈 증가
               - 상호작용이 없는 컴포넌트는 Next에서 사전렌더링시에만 사용되고(ServerComponent),상호작용이있는 컴포넌트는 (Client Component)는 번들로 포함
          ```
          Page Router - 페이지 이동 시 (jsbundle, jsonData)
          AppRouter - 페이지 이동 시 (RSC payload, ClientComponentBundle)
     - Next.js는 필요한 부분만 클라이언트 컴포넌트를 사용할 것을 권장
     - 서버컴포넌트는 사전 렌더링을 할 때 한번 진행 / 클라이언트 컴포넌트는 사전렌더링시 한번, 하이드레이션시에도 한번 진행됨
     - 주의사항
          - 서버컴포넌트에는 브라우저에서 실행될 코드가 포함되면 안됨
          - 클라이언트 컴포넌트는 클라이언트에서만 실행되지 않는다
               - 사전렌더링을 위해 서버에서 1번 실행, 하이드레이션을 위해 클라이언트에서 1번 실행
          - 클라이언트컴포넌트는 서버 컴포넌트를 import 할 수 없음
               - 클라이언트에는 서버 컴포넌트가 존재하지않음
               - 만약 import하는 경우 Next가 자동으로 클라이언트컴포넌트로 변환
          - 서버컴포넌트에서 클라이언트컴포넌트에게 직렬화되지 않는 Props는 전달 불가능함
               - 자바스크립트에서 함수는 직렬화가 될 수 없음 (Props전달 불가능)
                    - RSC payload는 JSON형태로 직렬화된 데이터임. 
                    - 서버컴포넌트는 RSC payload의 형태로 클라이언트는 이 데이터를 바탕으로 HTML을 파싱함
     - 페이지 라우팅
          - 페이지 라우팅시, 해당 페이지 JS Bundle과 PSC payload를 함께 전달
               - PSC payload를 바탕으로 HTML 파싱
          - 프리패칭 역시, PSC payload와 JS Bundle을 먼저 받아옴
               - (참고) SSG의 경우는 JS Bundle까지, SSR경우는 PSC payload만 받아옴
               - JS Bundle을 실제 이동에만 받아옴
               - 다이나믹 라우팅, useRouter를 사용하는 경우에는 자동으로 SSR 페이지로 분류
