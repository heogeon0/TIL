## 오늘 배운 내용
- 데이터 패칭
     - NEXT에서는 SSR, SSG, ISR 세가지 방법 존재
          - SSR방식은 미리 서버에서 필요한 데이터를 받아오지만, 서버가 느려질경우 오히려, FCP가 느려질 수 있음
- SSR
     - 브라우저의 접속 요청이 들어올때마다, 필요한 데이터 조회
     - `InferGetServerSidePropsType<T>` `getServerSideProps`함수의 `return`타입을 자동으로 추론해줌
- SSG
     - 빌드타임에 필요 데이터 조회
     - 만약 유저가 ssg로 만든 페이저가아니라, 다른 페이지로 접근 후, 클라이언트 네비게이션으로 이동한다면?
          - Next는 html과 json 둘다 만들어 놓기때문에, json 파일을 서빙 
     - Next 페이지는 기본값이 SSG로 동작함. `getStaticProps`를 사용하면 빌드 시 필요한 데이터를 받아옴
     - `getStaticPaths`를 통해 동적 페이지도 SSG 설정이 가능함
          - fallback : 미리 생성되지 않은 경로로 유저가 접근했을 때에 동작 설정
               - false: 404페이지 렌더링
               - blocking: 실시간으로 사전렌더링 (SSR) 
               - true: 즉시 생성 + 페이지만 미리 반환(Props가 없는데이터) -> Props 호출 후 Props만 다시 재전송
                    - `router.isFallback`옵션을 통해 `fallback`상태(props를 받아오고있는상태)임을 알 수 있음
