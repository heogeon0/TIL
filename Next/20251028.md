## 오늘 배운 내용
- 서버액션
     - 서버액션 이후 데이터 갱신
          - 서버액션이 성공했을때, 서버컴포넌트를 갱신할 필요가 있음
               - `revalidatePath(path, "page"|| "layout")`: 서버페이지 컴포넌트를 다시 렌더링시키는 함수
                    - 주소만 있는 경우 해당 주소만 재검증
                    - `page`와 함께쓰면 특정 경로의 모든 동적 페이지를 재검증
                    - `layout` 특정 레이아웃을 갖는 모든 페이지 재검증
                    - `revalidate('/', layout)` : 모든 데이터 재검증
                    - `revalidateTag(tagId)`: 특정 태그를 사용하는 `fetch`모두 삭제
                    - 데이터 캐시가 적용되어있는 경우에는 해당 페이지에 모든 캐시가 삭제됨
                    - 풀라우트캐시도 삭제 -> 사실상 풀라우트캐시는 필요없는 데이터가되며 다시 접속했을떄, 다이나믹페이지로 만들어진 페이지가 풀라우트캐시로 저장됨
                         - 리밸리데이터 당시에는 새로 불러온 데이터를 풀라우트캐시에 넣지 않음. 그 이유는 revalidate 이후 최신의 데이터를 제공하기 위함
     - 클라이언트에서의 서버액션
          - `useActionState` : 리액트 19버전이후로 나온 폼에 대한 상태를 관리하는 함수
          - `const [state, formAction, isPending] = useActionState(fn, initialState);`
               - 반환값
                    - state: 현재 상태값(폼의 결과값)
                    - formAction: 폼의 action prop에 전달할 수 있는 함수
                    - isPending: 액션이 진행 중인지 나타내는 boolean
               - 매게변수
                    - fn: 폼이 제출되거나 버튼이 눌렸을 때 호출될 함수. 첫 번째 인자로 이전 상태를, 두 번째 인자로 폼 데이터를 받습니다
                    - initialState: 초기 상태값
