## 키워드
#NEXT #풀라우트캐시

## 오늘 배운 내용
- 풀라우트캐시
     - 빌드타임에 특정 페이지를 캐시해놓는 방식 (SSG방식과 매우 유사)
          - static page에만 적용됨
               - dynamic page
                    1. fetch사용 시 쿠키를 사용하지 않는 컴포넌트를 포함할 때
                    2. 동적함수(쿠키, 헤더, 쿼리스트링)을 사용하는 컴포넌트가 있을 때
               - static page
                    - 다이나믹 페이지가아닌 모든 페이지
     - 풀라우트캐시도 revalidate도 가능 (ISR)과 유사한 기능
          - fetch 사용시 revalidate를 사용하는 경우 동일한 유효기간을 가짐
     - 동적 라우팅에 풀라우팅캐시 적용하는법
          - generateStaticParams 의 return을 정의
               - 이 함수를 사용하면 항상 생성된 페이지들을 풀라우팅캐싱함
     - 강제로 Static, Dynamic 페이지로 설정(라우트 세그먼트) -> 사용하지않는것 권장
          - `export const dynamic = '옵션'
          - auto: 기본값
          - force-dynamic: 강제 다이나믹페이지화
          - force-static: 강제 스태틱페이지 화 (동적 함수는 undefined됨, fetch는 강제 캐싱)
          - error: 스태틱페이지로 시도하고 안되면 에러
- 클라이언트 라우터 캐시
     - 브라우저 라우터 캐시
          - RSC payload 데이터 중에서 레이아웃을 담당하는 정보는 클라이언트 라우터캐시에 저장
               - 동일한 레이아웃을 중복해서 받는것을 방지
               
참고: 'use client'를 사용하는 컴포넌트를 리액트 빌드타임에서 접근을 막는방법 -> Suspense를 활용해서 클라이언트 컴포넌트를 감싸기
참고1: 페이지 컴포넌트안에서 notFound 함수를 호출하면 404페이지로 리다이렉트
